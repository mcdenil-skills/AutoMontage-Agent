# Motion-kit: слой ролика из готовых деталей и автоматические проверки

Эта инструкция – для того, кто собирает motion-слой ролика: для человека и для агента.
Здесь весь путь от пустой папки слоя до preview в пульте, устройство слоя, детали kit,
все проверки G1–G12 и что делать, если проверка остановила работу.


### Рабочее качество перед motion-слоем

Перед `automontage layer new` соберите `automontage master --project-dir projects/<id>
--edit edit/vNN-source.json`. По умолчанию `--quality 1080p` уменьшает короткую сторону до
1080, сохраняя пропорции и FPS; маленькие исходники не увеличиваются. Для родного размера
(включая 4K) явно задайте `--quality source` (алиасы `4k`, `native`). Нечётная сторона
без уменьшения округляется вниз на один пиксель: кодировщику нужны чётные размеры.
Если нарезка не нужна, агент создаёт source-edit с одним `keep` на всю запись по границам
кадров и с текущей `sourceRevision`. После master используйте активный `source.localPath`
и соответствующий `transcript.words` из `project.json`. Master не меняет оригинал.

Слой наследует размер рабочего исходника. Старый 4K-слой после нового 1080p master нужно
пересобрать через `layer new`: G6 остановит размер, не совпадающий с активным исходником.
Preview ограничивает длинную сторону 1920: для 1080×1920 масштаб 1, для 2160×3840 – 0,5.
Preview, собранные раньше в половину композиции, остаются действительными: утверждение
принимает и прежний размер, пересобирать их не нужно. Утверждённые версии не переписываются.

**Черновая нарезка до слоя.** Если автор смотрит сокращение до графики (`automontage roughcut`,
запись `project.json.roughCut`), `master` и `layer new` ждут его решения. Пока нарезка ждёт автора
(`status: review`), обе команды отказывают – до слота очереди и до создания папки слоя. Снять отказ
может только автор: кнопка «Нарезка готова» в пульте или его явные слова в чате
(`automontage roughcut confirm`). После подтверждения master собирается из
`edit/roughcut-vNN.json` или из его копии `edit/vNN-source.json` с правками автора, а `layer new`
отказывает, пока master не поднял ревизию исходника: слой строится только на таймингах, которые
автор видел. Первый же master завершает этап. Проекты без нарезки эти проверки не затрагивают.

## Зачем это нужно

Раньше каждый motion-слой собирался почти с нуля: своя камера, свои карточки, свой звук.
Ошибки (длинный план без склейки, текст за краем кадра, голос в звуке слоя) находились
только глазами, уже после долгого рендера.

Теперь слой собирается из готовых деталей движка – это и есть **motion-kit**. Ролик
описывает только режиссуру (`src/plan.js`) и дизайн своих карточек (`src/scenes.jsx`).
Камера, вставки, звуки и субтитры берутся из kit. Поэтому движок заранее знает, что
будет на каждом кадре, и проверяет это автоматически:

- `layer check` – по плану, за секунды, ещё до рендера (собирает только `layer.json`,
  слова, звуки и `plan.js`; ошибки в `scenes.jsx` видны только на `layer render`);
- `layer render` – по готовому видео слоя: длина и звук;
- `automontage preview` – перед публикацией: баланс голоса и музыки.

Если объективная проверка не пройдена, preview не публикуется, и в пульте остаётся прошлый.
Вкусовые проверки только предупреждают.

## Словарик

- **Safe-зона** – часть кадра, где текст не закроют кнопки и подписи соцсети.
- **Джамп-кат** – резкая смена крупности или положения спикера, чтобы кадр «ожил».
- **Панч-ин** – быстрый короткий наезд камеры на спикера для акцента.
- **Cue** – одно звуковое событие слоя: какой звук и на каком кадре ударит.
- **Манифест** – файл `out/manifest.json`: что будет на каждом кадре слоя; по нему работают проверки.
- **LU** – единица громкости на слух (как децибелы, но с поправкой на то, как слышит человек).
- **Ducking (sidechain)** – музыка сама становится тише, пока звучит голос.
- **Waiver (исключение)** – разрешение пропустить стоп одной проверки, записанное в плане с причиной.

## Что нужно заранее

- Папка проекта `projects/<ролик>/` с `project.json`, видео-исходником и локальным
  транскриптом (`transcript/words.json`). Их создаёт обычный старт ролика: передайте видео
  агенту ([инструкция монтажа, шаг 3](MONTAGE-GUIDE.md#3-передать-видео-агенту)) – он создаст
  проект, скопирует исходник и расшифрует его локально через faster-whisper.
- Исходник – видео, а не аудио и не картинка. Повёрнутое телефонное видео не подходит:
  сначала соберите мастер (`automontage master`) или перекодируйте его.
- По желанию – локальная библиотека звуков (раздел [«Звуки»](#звуки)). Без неё слой
  собирается без эффектов.
- По желанию – бесплатный ключ `PEXELS_API_KEY` для поиска стока (раздел [«Сток»](#сток)).
  Без него всё остальное работает. Ключ не отправляют в чат: он лежит в `.env` движка
  или в окружении и читается только локально.

## Путь нового ролика

Ниже `projects/<ролик>` – папка проекта, `motion-v01` – первый слой. Из папки движка
вместо `automontage` можно писать `node scripts/cli.js`.

```bash
# 1. Создать слой из шаблона
automontage layer new --project-dir projects/<ролик>

# 2. Править motion-v01/src/plan.js и motion-v01/src/scenes.jsx, после каждой правки:
automontage layer check --project-dir projects/<ролик> --layer motion-v01

# 3. По желанию: сток Pexels под вставку stock-1 из plan.js
automontage layer stock --project-dir projects/<ролик> --layer motion-v01 \
  --query "developer at laptop" --query-original "сижу за ноутбуком" --insert stock-1

# 4. Рендер слоя и проверка готового видео
automontage layer render --project-dir projects/<ролик> --layer motion-v01

# 5. Импорт проверенного рендера
automontage layer import --project-dir projects/<ролик> \
  --file projects/<ролик>/motion-v01/renders/layer-01.mp4

# 6. Черновик brief со слоем (ссылку ассета печатает layer import)
automontage layer brief --project-dir projects/<ролик> \
  --asset assets/broll/video/<id>/media.mp4 \
  --title "Название ролика" --head-cream "Подпись" --head-orange "акцент"

# 7. Полный preview (путь brief печатает layer brief)
automontage preview --project-dir projects/<ролик> --brief brief/vNN-draft.lesson.json

# 8. Контакт-лист preview и кадры вокруг правок пульта
automontage layer sheet --project-dir projects/<ролик>
```

`layer new`, `layer render`, `layer import` и `layer brief` в конце печатают строку «Дальше: …»
с готовой следующей командой.

Что делает каждый шаг:

1. **`layer new`** занимает следующую свободную папку `motion-vNN` (номера не
   переиспользуются) и копирует в неё шаблон, копию исходника (`public/speaker.mp4`),
   шрифты, звуки из библиотеки и заглушки стока и скриншота. `--dir motion-v05` задаёт имя
   вручную, `--profile avatar|live` – профиль проверок (по умолчанию `avatar`).
   Прерванный `layer new` (Ctrl+C, закрытое окно) убирает недостроенную папку сам.
2. **`layer check`** строит план, пишет `motion-v01/out/manifest.json` и прогоняет гейты
   G1–G5 и G9–G11. Отчёт – `qa/layer-motion-v01-check.txt` (и `.json`) в папке проекта.
   Он собирает только `layer.json`, `words.js`, `sfx-library.js` и `plan.js`. Ошибки в
   `scenes.jsx` (опечатка, `CAPTION_FONT` не из `FONTS`, текст карточки не влезает в `box`)
   он не видит – они проявятся только на `layer render` и в preview.
3. **`layer stock`** находит клип на Pexels, режет его под размер и FPS слоя и под длину
   вставки (`--sec`, иначе длина `--insert`, иначе 2,5 с) и кладёт в `public/stock/`. В `plan.js` его ставите вы (команда печатает, какой `src` вписать).
4. **`layer render`** сначала сам повторяет `layer check`, ждёт слот общей очереди, рендерит
   слой Remotion, нормализует видео и звук и проверяет G6 и G7. Готовый файл –
   `motion-v01/renders/layer-01.mp4`, отчёт – `qa/layer-motion-v01-render-01.txt`.
5. **`layer import`** принимает только проверенный рендер и кладёт его в ассеты проекта
   (`assets/broll/video/<id>/media.mp4`) тем же путём, что импорт в Review. Запись о слое
   попадает в реестр `qa/layer-imports.json` – по нему preview узнаёт слой kit.
6. **`layer brief`** публикует черновик brief: одна сцена `broll` на весь ролик играет слой,
   голос идёт из исходника по общему таймкоду. Brief только черновик: утверждает человек
   после просмотра preview.
7. **`automontage preview`** собирает preview и перед публикацией проверяет G8 (баланс
   голоса и музыки) и то, что слой прошёл `layer render` и импорт.
8. **`layer sheet`** делает контакт-лист текущего preview с рамкой safe-зоны, полоски кадров
   вокруг новых правок пульта и проверяет G12 (пустые кадры).

После этого ролик ждёт решения в пульте. Утверждает только человек: кнопкой «Утверждаю»
в пульте или словом «утверждаю» в чате.

Если нужно поправить только написание слов в субтитрах – правьте `spelling.json` и
запускайте `automontage layer words --project-dir projects/<ролик> --layer motion-v01`.
Команда заново пишет `src/words.js` и предупреждает о ключах, которых нет в транскрипте.

## Что лежит в папке слоя

```text
motion-vNN/
  layer.json          размер, FPS, длина, точка лица, профиль, громкость звуков, исходник
  spelling.json       {"cloudcode": "Claude Code"} – написание слов в субтитрах
  README.md           короткая памятка слоя
  src/index.jsx       регистрирует композицию               (не править)
  src/Root.jsx        собирает слой из деталей kit            (не править)
  src/plan.js         режиссура ролика                        (правите вы)
  src/scenes.jsx      дизайн карточек, вставок и шрифты       (правите вы)
  src/words.js        слова транскрипта                       (генерирует layer new / layer words)
  src/sfx-library.js  звуки слоя: файл, длина, пик, роль      (генерирует layer new)
  public/             speaker.mp4, fonts/, sfx/, stock/, shots/, SOURCE.md
  out/manifest.json   что будет на каждом кадре – для гейтов  (пишет layer check)
  renders/            layer-NN.mp4                            (пишет layer render)
```

`Root.jsx` и `layer check` собирают слой одной и той же функцией `compilePlan`. Поэтому
гейт проверяет ровно то, что потом рендерится.

### layer.json

```json
{
  "version": 1, "composition": "Layer", "fps": 25, "width": 1080, "height": 1920,
  "durationInFrames": 1500, "face": { "x": 540, "y": 787 }, "profile": "avatar",
  "sfxMasterDb": -5, "speaker": { "src": "speaker.mp4", "lastFrame": 1499 },
  "source": { "localPath": "input/source.mp4", "sha256": "…", "size": 52428800, "mtimeMs": 1790000000000, "revision": 1 }
}
```

- `face` – точка лица в пикселях кадра исходника. От неё камера строит планы. `layer new`
  ставит её по умолчанию в 0,5 ширины и 0,41 высоты: в проекте точка лица не хранится.
  У аватара голова обычно выше – **поправьте `face` в `layer.json`** по кадру исходника.
- `sfxMasterDb` – общая громкость звуков слоя в дБ, число не больше 0. По умолчанию −5 дБ.
- `composition` – имя композиции Remotion слоя (`Layer`). Только латинские буквы и цифры, дальше
  ещё `-` (правило id Remotion): имя встаёт аргументом команды Remotion, и значение вида `--env-file=…` команды
  слоя отклоняют.
- `source` – от какого исходника собран слой (путь, sha256, размер, время изменения,
  ревизия). Если исходник проекта сменился, `layer words`, `layer check` и `layer render`
  отказываются: кадры и слова разошлись бы с новым исходником. Нужен новый слой.
- Размер, FPS и длина равны исходнику. Не меняйте их руками: G6 это остановит.

### План слоя (LayerPlan)

`src/plan.js` экспортирует `export default function buildPlan(ctx)`. Функция синхронная и
возвращает объект. `ctx` – это `layer.json` плюс `words` и `sfxLibrary`. Все времена в
плане – секунды исходника (общий таймкод), kit сам переводит их в кадры.

```js
{
  hook: 'speaker' | 'enumeration',
  camera: {
    face: { x, y },                       // точка лица, px кадра исходника
    maxScale: 1.25,                       // необязательно
    presets: { NAME: { s, dx, dy, fill } },   // свои пресеты, необязательно
    shots: [{ at, preset, drift: 'in' | 'out' | 'none', dx, dy }],   // первый at = 0
    punches: [{ at, until, k: 1.15 }],    // панч-ин
    blurs: [{ from, to, px: 20 }],        // размытие спикера под графикой
    aways: [{ from, to }],                // спикер уходит из кадра
  },
  items: [{ id, kind: 'text' | 'card' | 'media', at, until, box: { x, y, w, h }, rot,
            enter: { kind: 'pop' | 'fly' | 'mask' | 'cut', from: [dx, dy] },
            exit: { frames: 5, dir: 'down' | 'up' }, life: { parallax: 8 }, bleed,
            sfx: 'pop' | { name, vol, leadFrames } | null,
            type: { from, to, sfx }, props: { … } }],
  // bleed: true – элемент нарочно выходит за край кадра (фон, декор); G5 его не проверяет
  inserts: [{ id, kind: 'stock' | 'screen' | 'donor' | 'scene', from, to, src, cover, kb: [1.03, 1.1], sfx }],
  sfx: [{ at, name, vol, prio }],         // звуки вне элементов
  captions: false | { chunk: { … }, lane: { x, y, w, h }, hide: [{ from, to }] },
  waivers: [{ gate: 'G1' | 'G4' | 'G11', reason }],
}
```

Главные правила вставок:

- `cover` по умолчанию `true` у всех, кроме `donor`. Вставки `stock`, `screen` и `scene`
  всегда закрывают спикера: `cover: false` у них – ошибка плана.
- `donor` без `cover` – оверлей: спикер виден, план спикера для G1 продолжается,
  субтитры остаются поверх. Полноэкранный донор ставьте с `cover: true`, иначе G1 даст
  ложный стоп.
- Закрывающая вставка не короче 0,68 с при 25 fps (закрытие + выход камеры + 1 кадр):
  иначе камера не успеет вернуть спикера.
- `kb` – пара чисел не меньше 1 (медленный наезд Ken Burns).
- Сток рисует `StockInsert`, вставки `screen` и `scene` – ваш `scenes.jsx` через
  `FullscreenReveal`.

### Правила plan.js

- `plan.js` импортирует только `@automontage/motion-kit/core` и файлы внутри своего слоя.
  `scenes.jsx` и другие React-файлы подключает `Root.jsx`, план ссылается на них по `id`.
  `process.env` в плане пуст. Другой импорт – `layer check` остановится и назовёт файл.
- Это ограждение от случайных ошибок, а не песочница: динамический `require`, `eval` и
  `globalThis.process` оно не ловит. `layer check` выполняет `plan.js` – **не запускайте
  его на чужих слоях**, которым не доверяете.
- Все тексты и цифры на экране – только из речи (`src/words.js`), не придуманные.
- Ошибка в `plan.js` показывает строку в `src/plan.js`, а не в собранном файле.

### Манифест и отчёт

`layer check` пишет манифест `out/manifest.json` – что будет на каждом кадре:

```js
{ version: 1, kitVersion, fps, width, height, durationInFrames, maxScale,
  camera: { s: [], requested: [], base: [], dx: [], dy: [], blur: [], opacity: [] },  // по кадру
  texts: [{ id, from, frames: [[l, t, r, b] | null] } | { id, from, until, static: [l, t, r, b] }],
  inserts: [{ id, kind, from, to, cover, src }],
  cues: { kept: [{ id, name, startFrame, hitFrame, durationFrames, notable, bed }],
          dropped: [{ id, name, hitFrame, notable, conflictWith, reason }] },
  hook, waivers }
```

- `camera.base` – масштаб пресета с дрейфом, до панчей и до предела `maxScale`. По нему G3
  отличает слишком крупный пресет от панча, упёршегося в предел.
- `cues.kept` – звуки, которые останутся; `durationFrames` задаёт окна эффектов для G7.
  `cues.dropped` – звуки, которые kit убрал из-за тесноты (сигнал для G9).
- Субтитры в `texts` называются `caption-<n>`, после окна `hide` – `caption-<n>b`, `caption-<n>c`…

Отчёт проверок лежит в `<проект>/qa/<имя>.json` и рядом `.txt` для чтения:

```js
{ version: 1, kind: 'layer-check' | 'layer-render' | 'preview', layer, profile, createdAt,
  inputs: [{ role, path, sha256 }],
  gates: [{ id, title, status: 'pass' | 'warn' | 'fail' | 'waived' | 'skipped',
            value, threshold, unit, spans: [{ fromSec, toSec, note }], hint }],
  unusedWaivers: [{ gate, reason }],
  summary: { status: 'pass' | 'warn' | 'fail' | 'error', fail, warn }, error }
```

Значки в тексте отчёта: ✅ пройдено, ⚠️ предупреждение, ❌ стоп, ☑️ снято исключением,
⏭️ не оценивалось. В отчёте видны первые три места ролика по каждому гейту, полный список –
в JSON.

`summary.status: 'error'` значит «оценить нельзя»: сборка плана упала, манифест повреждён,
рендер или замер не удался. Такой отчёт никогда не читается как «всё хорошо», даже если
список гейтов пуст или зелёный.

### Коды выхода

| Команда | 0 | 1 | 2 |
|---|---|---|---|
| `layer check`, `layer render` | пройдено или только предупреждения | стоп | оценить нельзя: ошибка до отчёта или отчёт с `error` |
| `layer new`, `words`, `import`, `brief`, `stock`, `sheet` | готово | ошибка (текст объясняет, что чинить) | – |
| `automontage preview` | preview опубликован | preview не опубликован (в том числе стоп проверок) | – |

`layer render` возвращает 1 и тогда, когда стоп дал его собственный `layer check`: рендер
при этом не запускается.

## Детали kit

Импорт зависит от файла:

- `plan.js` – только `@automontage/motion-kit/core` (чистые функции без React).
- `Root.jsx` и `scenes.jsx` – `@automontage/motion-kit` (всё из `core` плюс React-компоненты).

| Деталь | Где | Что делает |
|---|---|---|
| `autoShots(words, { endSec, maxSec: 2.2, minSec: 1.2, cycle })` | core | раскадровка по словам: план не длиннее `maxSec`, режет по концу слова, пресеты по кругу `W M W L W R` |

| `revealCard(width, height)` | core | стартовая карточка полноэкранной вставки (совпадает с safe-зоной) |

| `FontLoader({ faces, children })` | React | ворота шрифтов: `<FontLoader faces={FONTS}>…весь слой…</FontLoader>`, ничего не показывает до загрузки шрифтов |

Уточнения:

- `StockInsert`, `FullscreenReveal` и `KitBox` принимают только скомпилированные элементы
  (из `compilePlan`), а не сырые записи плана.
- `ScrollShot` в карточке прокручивает от конца входа (`from + ref25(8)`) до начала выхода
  (`until − ref25(5)`). `ref25(n, fps)` переводит n кадров эталона 25 fps в кадры ролика.
- `ShutterFlash` ставьте после входа карточки. Шаблон ставит вспышку только на оставшийся
  звук затвора: kit держит заметные звуки не чаще раза в секунду, значит и вспышки не чаще.
- Шрифты ролика выбирает `scenes.jsx` (`FONTS`, `CAPTION_FONT`). `CAPTION_FONT` обязан быть
  среди `FONTS`, иначе `Root.jsx` остановится с понятной ошибкой.

## Проверки G1–G12

Где считается: **check** – `layer check` (по плану, до рендера), **render** – `layer render`
(по готовому видео слоя), **preview** – внутри `automontage preview`, **sheet** – `layer sheet`.
Пороги в px заданы для короткой стороны кадра 1080 и масштабируются под ваш кадр.

| Гейт | Что проверяет | Порог | Где | Итог | Как чинить |
|---|---|---|---|---|---|
| G1 Ритм спикера | самый длинный план, где спикер резкий и в кадре без события | предупреждение > 2,2 с, стоп > 2,5 с | check | стоп, можно исключение | джамп-кат, панч-ин на общем плане, размытие под графикой или уход под вставку |
| G2 Слабые джамп-каты | смена плана, которую зритель не заметит | скачок 6–15 % масштаба или сдвиг лица 40–85 px | check | предупреждение | больше разница крупности или лицо в треть кадра |
| G3 Масштаб аватара | крупность спикера | не больше 1,25 | check | стоп выше 1,25 (только если план поднял `camera.maxScale`); предупреждение, если панч упёрся в предел или пресет крупнее предела | уменьшить пресет или ставить панч-ин на общем плане `W` |
| G4 Спикер в первые 3 с | спикер виден в начале ролика | каждый кадр первых 2 с – иначе стоп; 2–3 с – предупреждение | check | стоп, можно исключение | показать спикера (можно размытым) или объявить `hook: 'enumeration'` |

| G6 Длина слоя | длина, размер и FPS слоя равны исходнику | ±1 кадр | render | стоп | слой рендерится в размере и FPS исходника; при другой длине – новый слой через `layer new` |

| G9 Плотность звуков | звуки не слишком тесно и не у самых краёв слоя | любые через ≥ 0,3 с, заметные через ≥ 1 с, удар не в первые и последние 0,12 с | check | предупреждение | разнести звуки, убрать лишний заметный |
| G10 Стоковые вставки | хватает ли стока; не короче ли клип своей вставки | ≥ 3 вставок (≥ 2 в ролике короче 45 с) | check | предупреждение | `automontage layer stock --insert <id>` |
| G11 Чужое видео | донорское видео подряд | не дольше 3 с; вставки с паузой ≤ 0,5 с считаются одним прогоном | check | стоп, можно исключение | 2–3 с чужого ролика для контекста, дальше свои анимации |
| G12 Пустые кадры | не выпала ли графика или видео слоя | кадр пустой, если меньше 0,1 % пикселей с перепадом яркости больше 24 уровней | sheet | предупреждение | проверить слой и preview глазами на отмеченных секундах |

В отчёте preview есть ещё гейт **L «Слой прошёл layer render и импорт»**: слой из реестра
должен иметь целый, пройденный отчёт `layer render` для текущего исходника. Если нет – стоп.

### Подробности гейтов

- **G1.** Событие, которое разбивает план: джамп-кат (скачок масштаба от 15 % или сдвиг
  лица от 85 px), панч-ин (рост масштаба от 10 % примерно за 6 кадров эталона 25 fps), смена
  резкости (размытие от 6 px или уход спикера). Панч, который начинается на резе (новый план
  сразу с наездом), – одно событие, а не два. Если спикер ни разу не резкий и не в кадре –
  G1 `skipped`: оценивать нечего.
- **G3.** Kit сам не поднимает масштаб выше `camera.maxScale`. Стоп бывает, только если план
  задал `maxScale` больше 1,25.
- **G4.** Правило автора: спикер виден в первом кадре и все первые 2 секунды. Размытие и
  текст поверх допустимы, полное исчезновение – нет. Кадр под закрывающей (`cover`)
  вставкой считается «спикер не виден». Хук-перечисление (`hook: 'enumeration'`)
  освобождает от этого правила.
- **G5.** Гейт видит `box` элемента на каждом кадре анимации (влёт, перелёт, выход), а не
  сам текст внутри. Содержимое карточки обязано помещаться в свой `box` – вылезающий текст
  G5 не заметит. Элементы `kind: 'media'` и с `bleed: true` G5 не проверяет вовсе – и текст,
  нарисованный внутри них, тоже.
  Слепое пятно: манифест берёт движение только из анимации kit (`enter`, `exit`, поля плана).
  Сдвиг, который добавляет код сцены внутри `KitBox` (свои `dx`/`dy`, `extraScale`,
  покачивание, CSS `translate` к точке из пропсов), G5 не видит, а `KitBox` не обрезает детей.
  Пример: компонент сдвигает текст на `moveTo` y = 1600 – `layer check` зелёный, а в рендере
  текст ниже safe-зоны. Поэтому движение текста задавайте через `enter`/`exit` и поля плана, а
  не кодом сцены; текст внутри `media`/`bleed` и любой сдвиг из кода проверяйте кадрами и
  `layer sheet`.
- **G7.** Три сигнала: (1) слышимый звук слоя вне окон эффектов из манифеста – главный;
  (2) похожесть огибающей всей дорожки слоя на голос исходника со сдвигом до ±300 мс;
  (3) самое похожее на голос окно 2 с (только предупреждение и только если в нём есть звук
  вне эффектов). Если в слое совсем нет звука или он почти беззвучный – предупреждение.
  Слепые пятна: утечка голоса до 1 с под очень плотными эффектами и утечка тише −50 дБ
  могут пройти. Поэтому все видео внутри слоя обязаны быть `muted` – kit так и делает
  (`SpeakerLayer`, `StockInsert`).
- **G8.** Разница громкости голоса и музыки под речью, в LU: K-взвешивание BS.1770-4,
  блоки 50 мс только внутри окон речи, без гейтинга. Меряется по настоящим дорожкам
  preview: голос после нормализации, музыка после того же sidechain, что в миксе. Совет по
  `music.gainDb` не выходит за −60…0 дБ схемы brief, остаток предлагается добрать другим
  треком или ducking.
- **G9.** Kit сам прореживает звуки. G9 показывает, какие заметные звуки он убрал из-за
  тесноты, и удары у краёв слоя: движок плавно вводит и выводит звук слоя-сцены на 0,12 с.
- **G10.** `layer check` дополнительно меряет клип каждой stock-вставки: если он короче
  вставки больше чем на кадр, нет файла или `src` вне `public/`, будет предупреждение –
  последний кадр замрёт.
- **G11.** `cover` решает только видимость спикера и на длину прогона не влияет.
- **G12.** Берутся 16 кадров – середины 16 равных отрезков preview. Кадр уменьшается до
  135 px по ширине и переводится в серый. Ровный фон, виньетка и градиент дают почти ноль
  «краёв» – это и есть пустота. Кадр, который не удалось прочитать, тоже считается пустым.

### Исключения (waivers)

Исключение возможно только для **G1, G4 и G11** и только с причиной:

```js
waivers: [{ gate: 'G1', reason: 'длинный план – демонстрация экрана без склеек по просьбе автора' }],
```

- Другой гейт, пустая причина или не массив – ошибка сборки плана (`layer check` вернёт
  отчёт с `error`, код 2). `waivers: null` значит «исключений нет».
- Снятый гейт показан значком ☑️ с причиной, итог – «всё хорошо (исключений: N)».
- Исключение снимает только стоп. Если гейт прошёл или дал лишь предупреждение, отчёт
  покажет «ℹ️ исключение … не понадобилось – уберите его из plan.js».
- Исключение действует на весь гейт, а не на одно место ролика: исключение G1 для одной
  паузы прикроет и новую длинную паузу, добавленную позже. Проверяйте отчёт после правок.

## Барьер перед публикацией preview

`automontage preview` проверяет brief перед тем, как опубликовать preview. Строгость зависит
от того, есть ли в brief слой kit:

- **Слой kit** – видео сцены, чей sha256 записан в реестре `qa/layer-imports.json`
  (его пишет только `layer import`). Для такого preview гейты L и G8 строгие: стоп не даёт
  опубликовать preview, прошлый остаётся в пульте. Если отчёт проверок не удалось записать,
  preview тоже не публикуется. Команда печатает «preview не опубликован: проверки не
  пройдены (…)» и завершается кодом 1. Review Workbench показывает эту же причину под плеером
  (путь к отчёту – относительно проекта).
- **Любой другой ролик** (lesson без слоя kit, слой импортирован через Review) – публикация
  не блокируется. G8 здесь только справка: статус `skipped`, текст «для
  справки: разница голос/музыка X LU; без слоя kit G8 не оценивает баланс – музыку ведёт
  утверждённый рецепт», без советов по `music.gainDb`. Preview
  длиннее 3 минут (180 с) не меряется: справочный замер держит в памяти ~80 МБ на минуту и идёт
  внутри preview, а у preview из Review тайм-аут 10 минут. Для слоя kit ограничения нет.
- Видео, импортированное через Review, но названное как рендер слоя (`layer-NN.mp4`), даёт
  предупреждение L: «похоже на слой kit, но не импортировано через layer import».

Отчёт барьера – `qa/preview-<дата-время>-NN.txt` (и `.json`). Во входах (`inputs`) JSON-отчёта –
исходник (`source`), brief (`brief`) и каждый слой kit из реестра, который проверил гейт L
(`layer`: импортированный ассет и его sha256); пути относительно папки проекта. В подсказках
гейтов (например «замер не удался: …» с текстом ffmpeg) вместо полных путей – пути относительно
проекта или имена файлов.

**Известное ограничение.** Preview по motion-reel brief (`MotionReel`, ролик без камеры)
барьер не проходит вообще: для него гейты не запускаются. Слой kit, подключённый
media-сценой motion-reel, тоже обходит барьер. Собирайте слой kit через `layer brief` –
тогда барьер работает.

## Профили и коридор «голос – музыка»

- `avatar` – голос HeyGen/ElevenLabs и слой kit. Профиль по умолчанию.
- `live` – живая запись с микрофона.

Профиль выбирается при `layer new --profile`, хранится в `layer.json`, его можно разово
сменить флагом `--profile` у `layer check` и `layer render`. Профиль рендера попадает в
реестр импорта, и preview судит G8 по нему. Остальные пороги у профилей общие.

| Профиль | стоп ниже | предупреждение ниже | цель | предупреждение выше | стоп выше |
|---|---|---|---|---|---|
| `avatar` | 3 LU | 35 LU | 38 LU | 41 LU | 46 LU |
| `live` | 3 LU | 12 LU | 15 LU | 18 LU | 24 LU (не стоп) |

**Коридор `avatar` откалиброван по утверждённому эталонному preview** (29.09.2026, решение
владельца «по эталону»). Эталонный аватар-ролик с утверждённой музыкой (`gainDb −16`, ducking
`thresholdDb −40`, ratio 4) тем же способом замера дал разрыв 37,95 LU: под речью музыка
примерно на 38 LU тише голоса. Отсюда цель 38 LU, предупреждение вне 35–41 LU, стоп ниже 3 или
выше 46 LU. Число большое, потому что меряется настоящий микс: голос уже после нормализации
−14 LUFS, музыка после ducking по этому громкому голосу. Как и почему так мерили – в решениях
проекта ([DECISIONS.md](../DECISIONS.md), D-035).

**Коридор `live` не откалиброван.** Его числа 12/15/18/24 – старое правило `qa:preview`
«музыка на 12–18 дБ ниже голоса», переписанное в LU, а шкалы у них разные: утверждённый
аватар-баланс читается около 9 дБ по `qa:preview` и около 38 LU по G8. Поэтому для слоя kit с
профилем `live` вне 12–18 LU – только предупреждение с текстом «коридор live не откалиброван …
баланс сверьте на слух» и без совета по `music.gainDb`. Для live – стоп только если музыка
вровень с голосом или громче (< 3 LU): это нарушение на любой шкале. Стоп по всему коридору
остаётся для `avatar`, а стоп по поломкам звука («голос не звучит», «музыки под речью нет»,
«замер не удался») – для обоих профилей. Коридор уточнят по утверждённому живому ролику.

Что это значит на практике:

- Утверждённый рецепт музыки аватар-роликов (трек около −20 LUFS, `gainDb −16`, ducking
  `thresholdDb −40`, ratio 4, release 260) проходит G8. Начинайте с него.
- Если владелец попросил сделать музыку слышнее, уменьшите разрыв примерно на 6–8 LU
  (`music.gainDb` на столько же дБ выше). G8 покажет предупреждение – это ожидаемо: владелец
  сам попросил.
- Подсказку G8 «увеличьте/уменьшите `music.gainDb`» для слоя kit можно выполнять. Исключение –
  предупреждение «слишком громко под речью» после такой просьбы владельца: его не исправляйте.
- Музыку ведёт утверждённый рецепт, а не гейт: не меняйте её против вкуса владельца ради
  зелёного G8. Если G8 остановил preview, исправьте микс по подсказке или покажите число
  владельцу.

## Звуки

- Библиотека звуков локальная: папка с `<имя>.wav` и необязательным `library.json`.
  Путь – переменная `AUTOMONTAGE_SFX_DIR`; по умолчанию `projects/.library/sfx` в папке
  движка. Если `AUTOMONTAGE_SFX_DIR` указывает на несуществующую папку – это ошибка (опечатка
  в пути), а не «звуков нет». Если папки по умолчанию нет, слой собирается без эффектов, а
  `layer new` предупреждает об этом и называет путь, где искал библиотеку. В worktree и свежем
  клоне папки `projects/.library/sfx` обычно нет: укажите `AUTOMONTAGE_SFX_DIR` на свою
  библиотеку.
- Звуки в репозиторий не входят: лицензии библиотек вроде Mixkit запрещают раздачу.
  `layer new` копирует их в игнорируемую папку слоя (`public/sfx/`) и пишет в
  `public/SOURCE.md` лицензию и SHA-256 каждого файла.
- Имя файла – строчные латинские буквы, цифры и дефисы: `whoosh-in.wav`, `pop-soft.wav`.
  Звуковые файлы с другим именем (`Whoosh In.wav`, `.mp3`) не копируются, и `layer new`
  перечислит их в предупреждении; прочие файлы (README, LICENSE, скрытые) пропускаются молча.
- Роль звука – начало имени до первого дефиса: `whoosh-in` → `whoosh`. `pickSound` и
  `sfx: 'whoosh'` в плане ищут звук по имени или по роли. Заметные роли (для G9 и
  прореживания): `whoosh`, `swoosh`, `impact`, `riser`, `shutter`.
- `library.json` (всё необязательно):

  ```json
  { "license": "Mixkit Sound Effects Free License", "sourceUrl": "https://…",
    "sounds": { "impact-ring": { "role": "impact", "notable": true, "volume": 0.7, "peakSec": 0.44 } } }
  ```

  `volume` – от 0 до 1, `peakSec` – где удар (меньше длины звука). Без `peakSec` пик
  меряется сам. Звук выравнивается так, что удар приходится ровно на заданное время.
- Громкость всех эффектов слоя – `sfxMasterDb` в `layer.json` (по умолчанию −5 дБ).
- Вся библиотека копируется в `public/` каждого слоя (около 75 мс на файл) – держите её
  небольшой.

## Сток

`layer stock` ищет видео на Pexels тем же клиентом, что поиск B-roll в Review.

```bash
automontage layer stock --project-dir projects/<ролик> --layer motion-v01 \
  --query "english query" --query-original "фраза из речи" [--insert stock-1] [--sec 2.5] [--pick 1] [--list]
```

- `--query` – английский запрос (обязателен), `--query-original` – исходная фраза из речи
  (по умолчанию равна `--query`).
- `--list` – показать кандидатов и ничего не скачивать; `--pick N` – взять N-го (по
  умолчанию первого).
- Длина клипа: `--sec` (от 0,5 до 60 с), иначе длина вставки `--insert` (вверх до 0,1 с),
  иначе 2,5 с.
- Берутся только прямые mp4 с `videos.pexels.com`. Из вариантов файла выбирается самый
  маленький, который покрывает кадр слоя (не качаем 4K ради кадра 1080×1920). Файл до 256 МБ
  и до 4096 px.
- Клип обрезается и кадрируется под размер и FPS слоя, без звука:
  `public/stock/pexels-<id>.mp4`. Уже существующий файл не перезаписывается.
- В `public/SOURCE.md` добавляется строка из четырёх ячеек: файл | лицензия и автор |
  страница, запрос и отрезок | SHA-256.
- Команда не правит `plan.js`: она печатает, какой `src` вписать во вставку.
- Если клип короче запрошенного или короче вставки – предупреждение: последний кадр замрёт.

Без ключа команда объясняет, как положить свой клип вручную: mp4 в размере слоя в
`public/stock/`, `src` во вставке `{ kind: 'stock' }` и строка в `public/SOURCE.md`.
Ключ `PEXELS_API_KEY` берётся из окружения, затем из `.env` движка. Он уходит только в
заголовок запроса к `api.pexels.com` – не в сообщения, не в `SOURCE.md`, не на сервер с
видео и не в браузер.

## Рендер, импорт и brief – подробности

**`layer render`**

- Перед рендером занимает слот машинной очереди, общей с `layer import`, preview, final
  и `automontage master` на всех поддержанных ОС. По умолчанию один слот, ожидание до 3 часов,
  проверка каждые 5 с. Если ждал – проверяет план ещё раз, его могли поправить.
  `--no-wait` не ждёт: занятая очередь сразу даёт ошибку «машина занята: …».
- Тяжёлые команды запускайте в фоне; при ожидании смотрите `automontage queue`
  (задача, PID, начало и папка очереди), а не процессы через `ps`. Слот занят до конца
  операции и освобождается также при ошибке; project lease берётся после слота.
- Номер рендера занимается сразу: заявка – файл `renders/layer-NN.raw.mp4`. В этот же файл
  Remotion пишет сырой рендер, а после записи отчёта заявка удаляется. Два рендера одного
  слоя получат разные номера. Если рендер прервали, заявка остаётся (в ней может быть
  недописанное видео), а если прервали нормализацию – ещё и недописанный `layer-NN.mp4` без
  отчёта: следующий рендер возьмёт следующий номер, оба файла можно удалить. Номер, у
  которого есть готовый файл или отчёт, не переиспользуется.
- Remotion кодирует слой сразу в limited range (`yuv420p`, `color_range=tv`). После проверки
  ffprobe видео копируется, нормализуется только звук: 48 кГц AAC ровно на длину кадров слоя
  (хвост обрезается, недостающее дополняется тишиной). Если формат/range другой – безопасный
  fallback перекодирует видео. Звук слоя сохраняется: в нём эффекты (`audioMode: mix`).
- G6 меряет длину видеопотока слоя, а не контейнера.

**`layer import`**

- Принимается только сам рендер: файл внутри проекта, тот же путь и тот же sha256, что во
  входе `layer` самого свежего отчёта `layer render`. Копия файла в другом месте не
  проходит – команда подскажет, какой файл импортировать.
- Отчёт должен быть целым: без ошибки, не «стоп», с гейтами G6 и G7, итог совпадает с
  гейтами (итог, исправленный руками, не принимается) и собран для текущего исходника.
- Повторный импорт того же рендера не создаёт новый ассет, если прошлый цел.
- Проверенный соответствующий слой переупаковывается в master без повторного кодирования
  видео; несоответствующий перекодируется. WebM-прокси кодируется в четыре потока.
  Обычный HTTP-импорт Review не меняется. Полная проверка декодированием master и прокси
  с ограничениями времени и вывода, квоты и атомарная публикация сохраняются.
- Ограничения импорта: до 1 ГБ и до 30 минут.

**`layer brief`**

- `--asset` – ссылка `assets/broll/video/<id>/media.mp4` или sha256 ассета из реестра.
- `--title`, `--head-cream`, `--head-orange` обязательны, но это **подписи для Markdown и
  пульта**: сцена слоя идёт с `overlay: 'none'`, и в видео они не видны.
- `--audio mix` (по умолчанию) – звук слоя в миксе; `--audio mute` – без него (для слоя без
  звука).
- `--music <файл>` – музыка; файл снаружи копируется в `assets/music/` проекта.
  `--music-gain-db` по умолчанию −16 дБ для `avatar` и −12 дБ для `live`, `--music-start-sec`
  по умолчанию 0. Для `avatar` добавляется свой ducking (порог −40 дБ, ratio 4).
- Слой должен идти на весь ролик: короче исходника хотя бы на кадр или длиннее больше
  чем на кадр – отказ, нужен слой под этот исходник.
- Звук слоя в первые и последние 0,12 с приглушает огибающая сцены preview. Эффект хука
  ставьте не раньше 0,12 с. Слой держите одной сценой – так `layer brief` и делает.

**`layer sheet`**

- Работает с текущим preview проекта (`currentPreview` в `project.json`). Без preview –
  ошибка «сначала соберите preview».
- Контакт-лист 4×4 с рамкой safe-зоны – `qa/sheet-<первые 8 знаков sha256 preview>.jpg`.
- Для каждой новой правки пульта к этому preview – полоска из 5 кадров (−1, −0,5, 0, +0,5,
  +1 с): `qa/sheet-<…>-comment-<id правки>.jpg`.
- Команда только показывает и предупреждает: qa-отчёт не пишет, стоп не ставит, код 0.

## Ограничения

- Слой должен лежать вне `node_modules`: при установке движка через npm Remotion не
  транспилирует JSX оттуда.
- Анимации заданы в пикселях кадра 1080×1920 (по короткой стороне 1080) и масштабируются.
  Субтитры, их полоса и скругление вставки масштабируются по ширине кадра (1080 для
  вертикали, 1920 для горизонтали), поэтому на квадратном кадре субтитры заметно мельче.
- Проверка safe-зоны видит только текст внутри `KitBox` и `Subtitles`, и только `box`
  элемента, а не вылезающий из него текст. Элементы `kind: 'media'` и `bleed: true` она
  не проверяет, как и текст внутри них. Сдвиги, которые добавляет код сцены внутри `KitBox`
  (свои `dx`/`dy`, масштаб, покачивание, CSS `translate`), G5 тоже не видит: `KitBox` не
  обрезает детей, а манифест знает только анимацию kit. Подробности – в описании G5.
- Вспышки – не чаще раза в секунду: затвор – заметный звук, kit держит такие звуки ≥ 1 с
  друг от друга.
- Скриншоты – не выше ~16 000 px. Широкий скриншот не прокручивается и обрезается по бокам
  (cover): берите карточку близкой пропорции или высокий full-page.
- `radius` у `BrowserFrame` – в px эталона 1080: он умножается на короткую сторону кадра / 1080.
  `scale` задаёт этот множитель вручную вместо расчёта по кадру.
- Полноэкранный `screen` в 9:16 держите внутри safe-зоны вместе с рамкой браузера.
- На планах с заливкой (`L`, `R`, `top` и свои пресеты с `fill: true`) открытый край кадра
  закрыт размытой затемнённой копией спикера, а резкая копия уходит в неё мягким краем, без шва.
  Каждая сторона растушёвана на столько, сколько она открывает за план (сдвиг пресета,
  покачивание, дрейф, панч), но не больше 96 px и не меньше 8 px (для короткой стороны 1080).
  Поэтому у `L`/`R` мягкий только край со стороны сдвига, а бока `top` (масштаб 1,0) открывает
  лишь покачивание: полоса заливки и мягкий переход там не шире ~36 px, и настоящая картинка у
  бокового края остаётся резкой. Сама заливка видна полосой у края. Если
  полоса не нужна, задайте свой пресет без заливки, например `{ s: 1.2, dx: -200, fill: false }`:
  kit ограничит сдвиг запасом кадра (около 108 px при лице в центре), и масштаб останется в
  пределе `maxScale`. Запас до предела 1,25 у такого плана – около 4 % (1,25 / 1,2), а дрейф
  `out` в начале плана съедает и его: панч-ин 1,15 на нём упрётся в предел, и G3 предупредит.
  Панч ставьте на общем плане `W`; на таком плане берите `k` не больше 1,04 или пресет
  `s: 1.15` (запас около 8 %, сдвиг тогда около 81 px). Но ни `k` до 1,04, ни запас 8 % у
  `s: 1.15` не дают панча, который G1 засчитает событием: для этого нужен рост масштаба от
  10 %. Такой панч только оживляет план и длинный план не разбивает – панчи, которые должны
  считаться событием G1, ставьте на `W`.
- На Windows Remotion копирует `public/` слоя (с `speaker.mp4`) при каждом рендере, на
  macOS и Linux – ставит ссылку.

## Что делать, если…

**…`layer new` или `master` отказал из-за черновой нарезки**

| Сообщение | Что сделать |
|---|---|
| «черновая нарезка previews/roughcut-vNN.mp4 ждёт автора: …» | покажите автору копию в пульте («Черновая нарезка – посмотрите и отметьте оговорки») и ждите; «Нарезка готова» и `roughcut confirm` – только по решению автора, самому подтверждать нельзя |
| «нарезка подтверждена, но master по ней ещё не собран: automontage master …» | соберите master командой из сообщения (из `edit/roughcut-vNN.json` или из копии `edit/vNN-source.json` с правками автора), затем `layer new` |

**…`layer check` остановил работу**

| Сообщение | Что сделать |
|---|---|
| ❌ G1 «план N с без события» | на указанных секундах поставьте джамп-кат (другой пресет в `camera.shots`), панч-ин на общем плане, размытие под графикой или вставку; если длинный план нужен по смыслу – исключение G1 с причиной |
| ⚠️ G2 «скачок N %» / «сдвиг N px» | смените пресет на заметно другой (`W` → `M` или `L`/`R`) |
| ⚠️ / ❌ G3 | «пресет крупнее предела» – уменьшите `s` пресета; «панч-ин упёрся в предел» – ставьте панч на плане `W`; стоп – уберите `camera.maxScale` больше 1,25 |
| ❌ G4 «спикера не видно» | уберите закрывающую вставку и уход спикера из первых 2 с (размытие можно); или `hook: 'enumeration'`, если хук – перечисление объектов |
| ❌ G5 «элемент: слева до +N px» | переставьте `box` или уменьшите `enter.from`; для субтитров поправьте `captions.lane` |
| G5 зелёный, а в кадре текст за safe-зоной | G5 не видит сдвиг из кода сцены и текст внутри `media`/`bleed`: перенесите движение в `enter`/`exit` и поля плана, текст – в свой элемент с `box`; проверьте кадрами и `layer sheet` |
| ⚠️ G9 «kit убрал заметный звук» | разнесите заметные звуки минимум на 1 с или уберите один |
| ⚠️ G9 «перенесите не раньше 0,12 с» | сдвиньте удар от края слоя |
| ⚠️ G10 | добавьте сток по смыслу фраз: `layer stock --insert <id>`; «клип короче вставки» – новый клип под длину вставки |
| ❌ G11 | сократите донор до 2–3 с подряд; полноэкранный донор – `cover: true` |
| «оценить нельзя: … импортирует …» | в `plan.js` импорт не из `@automontage/motion-kit/core` и не из файла слоя – уберите его |
| «оценить нельзя: waivers[N] …» | исключение только для G1, G4, G11 и с непустой причиной |
| «оценить нельзя: манифест повреждён» | запустите `layer check` ещё раз; не правьте `out/manifest.json` руками |
| «исходник проекта сменился после создания слоя» | создайте новый слой `layer new` – старый собран на другом исходнике |
| «motion-v01 собран не до конца (нет layer.json)» | `layer new` оборвался: удалите папку или создайте новый слой |
| «папка слоя motion-v01 не найдена» | опечатка в `--layer` или слой ещё не создан |

| Сообщение | Что сделать |

| ❌ / ⚠️ G7 «посторонний звук вне эффектов» / «похоже на голос» | все `<OffthreadVideo>`/`<Video>` в `scenes.jsx` – с `muted`; голос только из исходника |

**…`automontage preview` не опубликовал preview**

| Сообщение | Что сделать |
|---|---|
| ❌ L «нет отчёта layer render» / «слой не прошёл проверки» | `layer render` → `layer import` → `layer brief` |
| ❌ L «реестр слоёв повреждён» | почините или удалите `qa/layer-imports.json` и повторите `layer import` |
| ⚠️ / ❌ G8 «музыку почти не слышно» (предупреждение выше 41 LU, стоп выше 46 LU для `avatar`) | увеличьте `music.gainDb` на указанное число дБ, ослабьте ducking или возьмите трек громче (раздел [«Профили»](#профили-и-коридор-голос--музыка)) |
| ⚠️ / ❌ G8 «слишком громко под речью» | уменьшите `music.gainDb` на указанное число дБ, усильте ducking или возьмите трек тише; предупреждение после просьбы владельца сделать музыку слышнее оставьте как есть |
| ⚠️ G8 «коридор live не откалиброван» | это не стоп: баланс голоса и музыки сверьте на слух или покажите число владельцу; `music.gainDb` по этому числу не меняйте |
| ❌ G8 «музыка вровень с голосом или громче – стоп и для live» | для live – стоп только если музыка вровень с голосом или громче (< 3 LU): сделайте музыку заметно тише голоса |
| ❌ G8 «голос не звучит» / «музыки под речью нет» | проверьте звук исходника и файл музыки; «голос не звучит» бывает и тогда, когда речь по транскрипту идёт после конца звуковой дорожки preview: проверьте, что звук preview не обрывается раньше видео |
| ❌ G8 «замер не удался: нет транскрипта …» | у проекта должен быть `transcript/words.json` |
| «отчёт проверок не записан» | папка `qa/` проекта должна быть обычной папкой и доступной для записи |

**…`layer sheet` показал ⚠️ G12**

Откройте контакт-лист и preview на отмеченных секундах. Пустой кадр бывает, когда выпала
графика, вставка без файла или видео слоя. Однотонный кадр по замыслу – не ошибка, это
только предупреждение.

**…команда пишет «qa/ должна быть папкой проекта, а не ссылкой или файлом»**

Отчёты, реестр слоёв и контакт-лист живут только в настоящей папке `qa/` проекта. Если на её
месте ссылка или файл, `layer check`, `layer render`, `layer import`, `layer sheet` отказывают, а
`automontage preview` не пишет отчёт (ролик без слоя kit при этом публикуется с предупреждением,
слой kit – нет). Уберите ссылку и верните обычную папку `qa/`.

**…`layer stock` отказал**

| Сообщение | Что сделать |
|---|---|
| «PEXELS_API_KEY не задан» | ключ необязателен: положите клип вручную (как в сообщении) или добавьте ключ в `.env` движка |
| «Pexels ничего не нашёл» / «нет прямой ссылки на mp4» | переформулируйте `--query` |
| «stock/pexels-N.mp4 уже есть» | выберите другой `--pick` или удалите старый файл, если он не нужен |
| «вставки X нет среди stock-вставок plan.js» | проверьте `id` вставки или добавьте `{ kind: 'stock' }` в `inserts` |

**…`layer new` отказал**

| Сообщение | Что сделать |
|---|---|
| «нет транскрипта …» | сначала расшифруйте исходник проекта |
| «в исходнике нет видеодорожки» / «исходник – картинка» | нужен видео-исходник |
| «исходник повёрнут на 90°» | соберите мастер `automontage master` или перекодируйте с поворотом в кадрах |
| «AUTOMONTAGE_SFX_DIR указывает на несуществующую папку» | исправьте путь или уберите переменную |
| «папка motion-vNN уже существует» | другое имя через `--dir` или без `--dir` |
| ⚠️ «библиотеки звуков нет: … собран без звуковых эффектов» (предупреждение, слой создан) | папки звуков по умолчанию нет (часто в worktree или свежем клоне): укажите `AUTOMONTAGE_SFX_DIR` на библиотеку или положите звуки в названную папку и создайте новый слой; слой без звуков подключайте с `--audio mute` |

**…окно Review закрылось вместе с терминалом**

`automontage review` завершается, когда закрывают окно терминала (сигнал SIGHUP), и
убирает за собой. `nohup` здесь не помогает. Для фона запускайте
`automontage review --project-dir projects/<ролик> & disown` (macOS, Linux) или через
`setsid` (Linux).

## Для разработчиков движка

- Детали kit – `src/motion-kit/`, гейты – `scripts/qa/`, команды – `scripts/layer/`,
  стартовые файлы слоя – `templates/motion-layer/`.
- Обычные тесты kit и гейтов входят в `npm test`.
- Настоящий Remotion-рендер kit и кадры шаблона – отдельно и **из корня движка**
  (`remotion.config.js` ищет kit от текущей папки):

  ```bash
  AUTOMONTAGE_TEST_MOTION_RENDER=1 node --test tests/motion-kit-render.test.js tests/layer-render-still.test.js
  ```

- Пороги гейтов – `scripts/qa/profiles.js`. Список гейтов, для которых возможно исключение,
  должен совпадать с `WAIVABLE_GATES` в kit – это проверяет тест.
