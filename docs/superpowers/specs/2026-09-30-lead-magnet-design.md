# Спецификация: Лид-магнит к ролику

**Статус:** approved – утверждено владельцем 2026-09-30
**Целевой релиз:** этап 1 – 1.11.0 (см. «Этапы»)
**База:** `main` на AutoMontage-Agent 1.10.0
**Источник:** discovery-интервью с автором, 2026-09-30; ручной прецедент лид-магнита, собранного
агентом вне движка
**Макеты экранов:** [2026-09-30-lead-magnet-mockups.html](2026-09-30-lead-magnet-mockups.html)
**Задача:** [#63](https://github.com/mcdenil-skills/AutoMontage-Agent/issues/63)

## Коротко

В концовке ролика автор часто обещает материал: «Напишите ГАЙД в комментариях, и я пришлю…».
Сейчас этот материал агент делает вручную в чате, и качество зависит от того, что агент вспомнит.
Новая возможность встраивает лид-магнит в «Пульт роликов». Агент сам находит обещание в сценарии
или расшифровке, а пульт спрашивает «Разработать лид-магнит?». Пользователь подтверждает параметры
и прикладывает референс дизайна. Агент параллельно с монтажом готовит страницу, PDF и тексты для
раздачи, а пользователь проверяет и утверждает их в том же пульте.

Схема ответственности остаётся прежней: **пульт показывает состояние и записывает решения,
работу делает агент, утверждает только человек.**

## Проблема

1. **Обещание пересказывают по памяти.** В прецеденте автор был уверен, что обещал
   «13 промптов», а в речи прозвучало «каждый промпт и 13 бесплатных скиллов». Материал,
   собранный не под то обещание, подводит зрителя.
2. **Стандарт подключается не всегда.** У автора уже был утверждённый стандарт лид-магнитов, но
   агент его пропустил и забыл блок призыва к действию в конце страницы. Стандарт должен
   подключаться сам и проверяться автоматически.
3. **Лид-магнит начинают после финала ролика.** Ролик готов, а раздавать нечего: публикация ждёт.
   Обещание при этом известно уже после расшифровки.
4. **Нет места для проверки.** Страницу смотрят вне пульта, телефонную ширину проверяют вручную,
   правки пишут словами в чате.
5. **Личное смешивается с общим.** Логотип, ссылки на каналы и голос автора нельзя класть в
   публичный движок, но у каждого пользователя они свои.

## Критерии успеха

1. Лид-магнит готов к утверждению не позже финального MP4 ролика, если пользователь ответил
   «Да» до утверждения preview.
2. В каждом лид-магните обещание процитировано дословно с таймкодом, и материал ему
   соответствует: число и тип обещанных единиц совпадают (автопроверка).
3. Ни один лид-магнит не проходит утверждение без блока призыва в конце, без проверки ширины
   390 px и без отчёта о проверке фактов.
4. Человек без своего брендбука получает аккуратную страницу с первого раза, без правок дизайна
   (проверяется одним наблюдаемым прогоном перед релизом этапа 2).
5. Ролик, для которого человек выбрал «Уже есть готовый», показывает именно выбранный
   лид-магнит без новой работы агента; одно кодовое слово может принадлежать нескольким
   материалам, а совпадение лишь предлагается.

## Пользователи

- **Автор с брендом.** Не разработчик, работает через агента в Claude Code или Codex. Приватный
  бренд-пак задаёт стиль, логотип и ссылки. Логотип обязателен.
- **Ученик или новичок.** Своего брендбука нет. Логотипа по умолчанию нет. Нужен приличный
  результат из коробки.

## Путь пользователя

```
Ролик:       исходник → расшифровка → черновик → preview → «Утверждаю» → финал
                            │
                            └ агент нашёл обещание (цитата + таймкод)
Лид-магнит:                 → плашка «Разработать?» → окно параметров → черновик
                              → проверка (компьютер / телефон) → правки → «Утверждаю» → файлы
```

1. **Агент находит обещание.** После расшифровки (или раньше, в утверждённом сценарии
   аватар-ролика) агент ищет призывы двух видов: кодовое слово в комментариях и «напишите мне
   в личку / в бота». Он сохраняет дословную цитату, таймкод начала и конца, кодовое слово,
   вид призыва и заранее заполненные параметры (формат, аудитория, тексты).
2. **Пульт спрашивает.** На обложке карточки появляется метка «🎁 Лид-магнит?». Внутри карточки
   над статусом видео показана плашка с цитатой, кнопкой «▶ послушать» и тремя кнопками:
   **«Разработать новый»**, **«Уже есть готовый ▾»**, **«Нет»**. Раздел карточки из-за вопроса
   не меняется: ролик в монтаже не выглядит так, будто ждёт пользователя.
   - Если в библиотеке уже есть лид-магнит с тем же кодовым словом, плашка подсказывает его.
   - «Уже есть готовый» открывает список утверждённых лид-магнитов с поиском. Совпадения по
     кодовому слову стоят первыми. Выбор привязывает ролик без новой работы агента.
   - «Нет» скрывает вопрос для этого кодового слова. В действиях карточки остаётся кнопка
     «Лид-магнит», чтобы передумать. Новое кодовое слово в новой версии ролика снова вызывает
     вопрос.
   - Если обещания в ролике нет, вопрос не появляется. Кнопка «Лид-магнит» в действиях
     доступна всегда.
3. **Окно параметров.** Все поля заранее заполнены агентом, пользователь только проверяет.
   Без правок это один клик «Отправить агенту».
   - Обещание: цитата, таймкод, «▶ послушать». Галочка «Делаем ровно под это обещание»
     обязательна.
   - Кодовое слово.
   - Формат: гайд по шагам, набор промптов, чек-лист, шпаргалка на один экран. Агент
     предлагает формат и объясняет почему.
   - Для кого (одна строка).
   - Дизайн: «Мой стиль», «По референсу», «Новый дизайн под тему», «Как прошлый лид-магнит».
   - Тексты для раздачи: сообщение в личку, пост в Telegram, подпись для Instagram. По
     умолчанию включены все три.
   - Пожелания (свободный текст).
4. **Агент готовит черновик.** Помощник агента (субагент) работает параллельно с монтажом:
   лид-магниту не нужен Remotion, и он не занимает очередь рендеров. Если чата с агентом нет, во
   вкладке есть «Скопировать для агента», чтобы открыть отдельный чат.
5. **Проверка.** Во вкладке «Лид-магнит» карточки живая страница показана «за стеклом», с
   переключателем «Компьютер / Телефон 390». Рядом три текста со счётчиками символов, отчёт
   каркаса и фактов. «Режим правок» позволяет кликнуть по блоку страницы и написать правку. Пульт
   запоминает блок, вид (компьютер или телефон) и снимок этого места.
6. **Утверждение.** Галочка «Я просмотрел страницу и тексты» и кнопка «Утверждаю лид-магнит».
   Кнопка заблокирована, пока каркас или проверка фактов не зелёные.
7. **Файлы.** В блоке «Файлы» лежат страница (один HTML-файл), PDF и три текста. У каждого
   текста есть «Скопировать», у всего — «Показать в папке».

|---|---|---|---|
| 1 | Где строить | Модуль внутри пульта AutoMontage с чёткой границей | Пульт, входящие и папки роликов уже работают; модуль можно вынести, если пульт станет отдельной программой |

| 11 | Что брать | Есть бренд – только композицию; нет бренда – всё; галочки переключаемы | Бренд не ломается случайно, новичок получает цельный вид |

| 14 | Просмотр | Живая страница в песочнице + «Компьютер / Телефон 390» | Кнопки и галочки проверяются руками |
| 15 | Правки | Клик по блоку, снимок места | Аналог «правки на секунде и кадре» у видео |
| 16 | Карточка | Вкладка «Лид-магнит»; раздел карточки – самое срочное из видео и лид-магнита | Как уже работают варианты ролика |
| 17 | Файлы этапа 1 | HTML одним файлом + PDF + три текста | Страница для ссылки, PDF для тех, кто любит файл |
| 18 | Публикация | Не в этапе 1; этап 3 – «папка публикации» | Надёжного бесплатного хостинга «одной кнопкой» для всех нет (см. приложение) |
| 19 | Новичок | 3 встроенные темы + короткая анкета бренда | Приличный результат без брендбука |

## Функциональные требования

### Этап 1 – обязательно (P0 спецификации)

**F1. Поиск обещания.** Агент записывает найденные призывы в `lead-magnet/offers.json` папки
ролика. Каждая запись: кодовое слово, вид (`comment-keyword` или `dm`), дословная цитата,
`startSec`/`endSec` по глобальному таймкоду исходника, ревизия source/transcript, из которой
взята цитата, подсказки для окна. Обещанные единицы извлекаются отдельно: «13 скиллов»,
«каждый промпт».
*Готово, когда:* на эталонном тесте расшифровки находится цитата, таймкод совпадает с
`words.json` до 0,1 с, а единицы разобраны.

**F2. Плашка и метка.** Пульт показывает метку на обложке и плашку в карточке для каждого
обещания, по которому ещё нет решения. Три кнопки записывают решение в `pult/lead-magnet.json`
папки ролика. Раздел карточки из-за плашки не меняется.
*Готово, когда:* «Нет» скрывает плашку после перезапуска пульта, а кнопка «Лид-магнит»
возвращает окно.

**F3. Окно параметров.** Модальное окно (первое в пульте) с полями из раздела «Путь», с
заполнением из `offers.json`. Без галочки обещания «Отправить агенту» неактивна. Отправка
записывает запрос в `pult/lead-magnet.json` и не создаёт других файлов.
Пункт 8 «Куда ведём в конце»: `brand` (по умолчанию), `link` (свой заголовок, надпись,
HTTPS-ссылка с UTM бренд-пака) или `none` (только соцсети). Последняя своя ссылка из библиотеки
подставляется в окно. Необязательное `params.cta` сохраняет выбор; старые запросы означают `brand`.
*Готово, когда:* запрос виден в `automontage inbox` одной строкой со всеми параметрами.

**F4. Референсы.** Загрузка картинок (PNG, JPG, WebP), HTML, PDF и ссылок. Галочки «Что взять»:
композиция, цвета, шрифты, по умолчанию по правилу 11. Поле «Что нравится». Требования
безопасности – в разделе «Безопасность».
*Готово, когда:* каждый тип сохраняется с SHA-256, а запрещённый тип или размер отклоняется
понятным сообщением.

**F5. Библиотека.** Лид-магниты живут в `projects/.lead-magnets/<id>/`, а не в папке одного
ролика. Ролики ссылаются на них. Лид-магнит знает все свои кодовые слова и ролики.
*Готово, когда:* ролики, явно привязанные через «Уже есть готовый», показывают один выбранный
лид-магнит; совпадение кодового слова лишь предлагает варианты и не запрещает несколько
материалов на одно слово.

**F6. Сборка агентом.** Проектный навык `lead-magnet` (для Claude Code и Codex) ведёт агента:
- подключает стиль из бренд-пака или встроенной темы;
- разбирает референс по галочкам;
- выполняет обещание дословно;
- проверяет факты вживую;
- собирает `page.html` одним файлом, `page.pdf`, три текста и внутренний `content.md`;
- снимает скриншоты для компьютера и для 390 px;
- запускает проверку каркаса.

Каждая сборка – новая ревизия `vNN/`.

**F7. Каркас и его проверка.** Команда `automontage lead-magnet check` проверяет пять пунктов.
Любой провал блокирует утверждение.
1. Цитата обещания есть на странице, обещанные единицы выполнены (число и тип).
2. В конце есть нижний блок со ссылками (`data-lm="cta"`) при любом режиме призыва,
   включая `none` с одними соцсетями. Если соцсетей нет, остаётся подсказка сохранить страницу.
   Правило проверки блока не меняется.
3. На ширине 390 px нет горизонтальной прокрутки и обрезанного текста.
4. Каждый блок промпта или команды имеет кнопку «Скопировать».
5. Логотип присутствует, если бренд-пак требует его (`logoRequired`).

Дополнительно проверяется:
- страница самодостаточна: нет внешних запросов;
- лимиты текстов: личка ≤ 1000, пост Telegram ≤ 1024, подпись Instagram ≤ 2200;
- в шапке нет слова «лид-магнит».

**F8. Проверка фактов.** Агент открывает каждую ссылку и проверяет команды установки, лицензии
и цифры. Отчёт `facts.json` хранит утверждение, источник, время и статус (`verified`, `failed`,
`unverifiable`). Любой статус, кроме `verified`, блокирует утверждение, пока агент не исправит
его или не уберёт утверждение со страницы.

**F9. Вкладка «Лид-магнит».** Вкладки «Видео | Лид-магнит 🎁» над плеером. На вкладке
лид-магнита есть:
- просмотр «за стеклом» с переключателем «Компьютер / Телефон 390»;
- тексты со счётчиками;
- отчёт каркаса и фактов;
- правки;
- утверждение;
- блок «Файлы»;
- «Скопировать для агента».

**F10. Правки кликом по блоку.** В «Режиме правок» клик по блоку страницы открывает поле правки.
Запись хранит ревизию, вид, id блока, рамку и снимок (PNG). Правка к тексту для раздачи
привязана к этому тексту. Удалять можно только правки со статусом «ждёт агента», как у видео.

**F11. Утверждение.** «Утверждаю лид-магнит» работает как утверждение видео. Пульт передаёт
билет на просмотренную ревизию: HMAC от id, ревизии и SHA-256 страницы. Движок
(`approveLeadMagnet`) повторно хеширует файл, проверяет каркас и факты и записывает статус
`approved`. Агент эту функцию и маршрут не вызывает никогда.

**F12. Статусы и разделы.** Статусы лид-магнита:
- «Агент готовит» – `working`;
- «Посмотрите и утвердите» – `waiting`;
- «Ждёт агента: N правок» – `working`;
- «Утверждён» – `ready`;
- «Обещание изменилось» – `waiting`.

Раздел карточки – самый срочный из статусов видео и лид-магнита. Подпись называет, что именно
ждёт: «Лид-магнит: посмотрите и утвердите».

**F13. Обещание изменилось.** Пульт сравнивает цитату утверждённого или готовящегося
лид-магнита с актуальным `offers.json`. Если цитата изменилась, он показывает старую
и новую цитаты и кнопки «Обновить под новое» и «Оставить как есть». Агент сам ничего не
переделывает. Если обещание пропало, доступна только «Оставить как есть».

**F14. Входящие.** `automontage inbox` получает строки:
- запрос лид-магнита;
- правку к блоку со снимком;
- запрос «Обновить под новое» при изменившемся обещании;
- запрос по воронке.

Привязка к готовому и «Оставить как есть» выполняются движком сразу при записи решения и во
входящие не попадают; «Обновить под новое» – попадает.

`automontage inbox --accept-lead <id> <запрос>` отмечает запись принятой. Правило архива D-030
распространяется и на лид-магниты.

**F15. Бренд-пак лид-магнитов.** Приватный пакет пользователя содержит `lead-magnet/brand.json`:
- токены цветов и шрифтов, файлы шрифтов;
- логотип и признак `logoRequired`;
- блок призыва по умолчанию: заголовок, текст, кнопки со ссылками и UTM-шаблоном;
- обязательный `socials`: до восьми постоянных ссылок автора (`network`, `label`, `url`),
  сети `telegram`, `instagram`, `youtube`, `vk`, `site`, HTTPS без логина и пароля;
  значки встроены в страницу, ссылки показаны внизу при любом выборе; без соцсетей — `[]`;
- голос: имена навыков и файл правил;
- образцы: id прошлых лид-магнитов.

Путь задаёт переменная `LEAD_MAGNET_BRAND`. Если она не задана, движок ищет папку
`lead-magnet/` рядом с папкой `THEMES_EXT`. Без бренд-пака используется встроенная нейтральная
тема, логотипа нет.

**F16. Воронка – только чтение.** Если у пользователя подключён поставщик воронок, агент
проверяет, есть ли автоматизация на кодовое слово, и пишет `funnel.json`. Пульт показывает
«Воронка на слово ГАЙД: есть / нет · проверено <время>». Первый поставщик – Chatplace через его
официальный MCP-сервер. Без поставщика блок скрыт.

### Этап 2 – важно (P1)

- **Новичок:**
  - три встроенные темы: светлая, тёмная, тёплая;
  - анкета бренда при первом «Разработать»: имя или ник, ссылки для блока призыва, логотип по
    желанию;
  - ответы сохраняются локально в `projects/.pult/lead-magnet-brand/` и не попадают в Git.
- **«Как прошлый лид-магнит»:** выбор утверждённого образца, агент повторяет его композицию и
  стиль.
- **Ссылка на страницу:** поле, куда пользователь вставляет адрес после ручной публикации.
  Тексты для раздачи получают эту ссылку.
- **Подключить или донастроить воронку.** Кнопка записывает запрос. Агент через MCP поставщика
  готовит **план изменений**: слово, ответы в комментариях, сообщение в личку, ссылку. Пульт
  показывает план, и только кнопка «Применить» пользователя запускает запись в сервис.
  Изменения живой воронки видят реальные подписчики, поэтому подтверждение двухшаговое.

### Этап 3 – позже (P2)

- **«Опубликовать».** Папка `publish/` содержит `index.html`, PDF и «карточку настройки»:
  кодовое слово и варианты его написания, три ответа на комментарий, личку со ссылкой, ссылку
  для Telegram-бота, текст для описания YouTube. Выгрузка на хостинг – необязательные адаптеры,
  только если у пользователя уже установлен и авторизован CLI.
- **Обложка-картинка** 1080×1350 для поста или сторис.
- **Сохранить как мой стиль:** из утверждённого лид-магнита по референсу сделать тему бренд-пака.

## Архитектура

### Где что лежит

```text
projects/<ролик>/
  lead-magnet/offers.json          # пишет агент: найденные обещания
  pult/lead-magnet.json            # пишет пульт: решения и запросы по обещаниям этого ролика
  pult/lead-magnet-refs/<sha>.<ext> # пишет пульт: загруженные референсы

projects/.lead-magnets/<YYYY.MM.DD_слово>/
  lead-magnet.json                 # паспорт: слова, обещание, ролики, параметры, ревизии, статус
  references/                      # референсы, скопированные агентом из запроса, с provenance
  v01/ page.html page.pdf content.md texts/{dm,telegram,instagram}.txt
       qa/{desktop.png,phone-390.png,check.json} facts.json
  funnel.json                      # пишет агент: состояние воронки у поставщика
  pult/comments.json, pult/frames/ # пишет пульт: правки к блокам и снимки
```

Правило «пульт пишет только в `pult/` и `projects/.pult/`» сохраняется: библиотека получает
свою папку `pult/` по тому же принципу, что и ролик. Утверждённую ревизию записывает движок, как
brief при утверждении видео.

### Новые схемы

`schema/lead-magnet.schema.json` (паспорт), `lead-magnet-offers.schema.json`,
`lead-magnet-requests.schema.json`, `lead-magnet-brand.schema.json`,
`lead-magnet-funnel.schema.json`. `project.schema.json` не меняется: связь ролика и лид-магнита
живёт в `offers.json` и `pult/lead-magnet.json`.

### Компоненты

| Компонент | Ответственность |
|---|---|
| `scripts/lead-magnet/` | паспорт, библиотека, `check` (каркас через Playwright), `approveLeadMagnet`, поиск по слову |
| `scripts/pult/` | статусы лид-магнита в карточках, новые маршруты, входящие |
| `pult/` | метка, плашка, окно параметров, вкладка, песочница просмотра, режим правок |
| `skills/lead-magnet/` | навык агента: сборка, факты, тексты, воронка; адаптеры `.claude/` и `.codex/` |

### Поставщик воронок

Движок описывает контракт, а не конкретный сервис. У контракта три действия:
- «проверить слово» – только чтение;
- «предложить план» – только чтение;
- «применить план» – запись после подтверждения в пульте.

Поставщик Chatplace – это инструкции навыка для официального MCP-сервера. Ключ хранится в
настройках MCP-клиента пользователя. Движок ключ не читает, и в `.env` движка он не нужен.
Неофициальные и снятые из браузера endpoint'ы в публичный репозиторий не попадают.

## Безопасность

- **Загрузка.** Отдельный маршрут принимает сырое тело только для разрешённых типов:
  - типы определяются по сигнатуре файла, а не по расширению;
  - предел размера: картинка ≤ 15 МБ, PDF ≤ 30 МБ, HTML ≤ 5 МБ;
  - имя файла генерирует сервер (SHA-256);
  - запись только в `pult/lead-magnet-refs/` папки ролика, без символических ссылок;
  - ссылка сохраняется только как текст (`http`/`https`), пульт по ней не ходит.
- **HTML-референс** никогда не открывается в пульте. Агент читает его как данные и снимает
  скриншоты в отдельном headless-браузере без доступа к пульту.
- **Просмотр страницы.** Отдельный маршрут отдаёт только `page.html` из ревизии в песочнице:
  - `iframe sandbox="allow-scripts"` без `allow-same-origin`;
  - CSP `default-src 'none'`, встроенные стили, скрипты, `data:`-картинки и шрифты;
  - `connect-src 'none'`: страница не видит ни пульт, ни интернет.

  Если страница ломается без сети, это ошибка самодостаточности, её ловит `check`. Маршрут
  медиа по-прежнему не отдаёт `.html`.
- **Правки кликом.** Скрипт выделения блоков добавляется сервером при выдаче (в файл не
  пишется). С пультом он общается только через `postMessage` с проверкой источника.
- **Утверждение.** Билет, повторный хеш, запрет утверждения из истории; агент не вызывает
  маршрут.
- **Воронка.** Запись в сервис – только после «Применить» в пульте. Ключи не попадают в пульт,
  логи и Git.
- **Регрессионные тесты:**
  - обход пути в загрузке;
  - подмена типа файла;
  - превышение размера;
  - HTML-референс, который пытается выполниться в пульте;
  - страница, которая пытается сделать сетевой запрос или обратиться к `parent`.

## Нефункциональные требования

- Всё работает локально и по подписке Claude Code или Codex, отдельные API-ключи не нужны.
  Ключ поставщика воронок нужен только для блока воронки и хранится у MCP-клиента.
- Сборка черновика ≤ 15 минут для гайда на 10 шагов (ориентир, не гейт).
- Пульт не зависает на библиотеке из 200 лид-магнитов (паспорт читается без HTML).
- Документация: `docs/PULT.md`, `docs/LEAD-MAGNET.md` (новый), `README.md`, `ARCHITECTURE.md`,
  `CHANGELOG.md`, `DECISIONS.md`, курс «Ролики с нуля» (глава о публикации).

## Вне рамок

- Пульт как отдельная программа, которая сама запускает Claude CLI или Codex CLI (отдельное
  интервью).
- Автоматическая публикация на хостинг в этапах 1–2.
- Прямая запись в Instagram, ManyChat или YouTube: открытого API для этого нет.
- Генерация картинок через платные API.
- Копирование текстов, изображений и брендинга референса.

## Открытые вопросы реализации

1. Работает ли копирование в буфер (`navigator.clipboard`) в песочнице без `allow-same-origin`,
   или нужен `allow="clipboard-write"` / запасной путь через `execCommand`. Проверить в Chrome
   и Edge.
2. PDF: печать Playwright из той же страницы (кнопки скрываются стилями печати) или отдельный
   шаблон. Начать с печати.
3. Id блоков для правок: агент ставит `data-lm-block` при сборке, `check` проверяет, что они
   есть у каждого раздела.
4. Точный формат билета утверждения лид-магнита, чтобы переиспользовать код `approveBrief`.
5. Точный список инструментов MCP Chatplace для чтения автоматизаций – снять при реализации F16
   из живого подключения, в `knowledge/`.

## Приложение: исследование публикации (2026-09-30)

- **Хостинга, который бесплатен, публикуется одной командой без аккаунта и стабильно
  открывается в России без VPN, не найдено.**
  - Cloudflare Pages публикуется одной командой, но в России фильтруется: из ответа проходят
    первые ~16 КБ, а самодостаточная страница больше.
  - GitHub Pages в 2026 году открывается с перебоями.
  - Notion недоступен из России; Telegraph не поддерживает скрипты и стили.
- **Автоответ.**
  - Официальные private replies Instagram: одно сообщение на комментарий в течение 7 дней.
    Нужны вебхук и приложение Meta, с ноутбука это не запустить.
  - У ManyChat нет API для создания сценариев.
  - Telegram-бот не пишет первым: нужна ссылка `t.me/<бот>?start=<слово>`.
  - На YouTube Shorts ссылки в описании и комментариях не кликаются.

  настройках, нужен платный тариф. Через MCP агент видит активные автоматизации и может создавать
  автоматизации по ключевому слову. Отдельной документации REST API на момент исследования не
  найдено.
