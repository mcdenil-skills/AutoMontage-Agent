# Очередь тяжёлых задач и меньше перекодирований – дизайн

**Дата:** 2026-10-02
**Основание:** аудит скорости монтажа 2026-10-02 (load average ≈ 100 на 8 ядрах при трёх роликах
параллельно), исследование кода и замеры на слое 1080×1920, 30 fps, 95 с (M1 Pro, 8 ядер, 16 ГБ,
фоновая нагрузка – запись экрана, load 8–17).

## Цель

1. Тяжёлые задачи движка (рендер слоя, импорт слоя, preview, финальный рендер, сборка исходника)
   на одной машине выполняются по очереди, а не одновременно.
2. Одна итерация «правка → новый preview» делает меньше полных перекодирований видео без потери
   проверок и качества.

## Замеры (1080p, 95 с)

| Шаг | Сейчас | Предлагается | Замер нового |
|---|---|---|---|
| Нормализация слоя после Remotion | libx264 medium crf 14, видео + звук: **80 с** | Remotion сам пишет limited range; нормализуется только звук, видео `-c:v copy` | **2,8 с** |
| Мастер при `layer import` | libx264 medium crf 18: **69 с** | для проверенного слоя – переупаковка `-c copy` | **0,3 с** |
| Прокси VP8 при `layer import` | `-threads 1`: **114–119 с** | `-threads 4 -cpu-used 4` | **26 с** |
| Проверка громкости в `finish.js` | декодирует и видео | `-vn` | −≈4 с |

Итого ≈ −4 мин на итерацию (замер полной итерации 1080p до изменений: слой 7:40, импорт 2:42,
preview 3:24 ≈ 14,5 мин).

**Проверки эквивалентности:**

- Remotion 4.0.504 с `ffmpegOverride` (`-vf scale=out_range=tv,format=yuv420p -color_range tv`
  перед выходным файлом): выход `yuv420p`, `color_range=tv`; против текущего пути (Remotion →
  нормализация) PSNR 47,3 дБ, SSIM 0,992; доля пикселей вне 16–235 – 0,01 % / 0,1 % (у текущего
  0,006 % / 0,06 %), перцентили 0,1/99,9 – 19/236 против 19/235, средняя яркость 107,98 против
  108,01. Новый путь сжимает видео один раз вместо двух.
- Remotion сам выбирает режим кодирования: при нехватке памяти – «Parallel encoding is disabled»,
  кадры JPEG кодируются отдельным шагом `stitcher`; иначе – `pre-stitcher`, а `stitcher` только
  копирует (`-c:v copy`). Override должен менять только аргументы, где есть `-c:v libx264`.
- Переупаковка нормализованного слоя совпадает с перекодированным мастером по всем полям, которые
  проверяет `verifyNormalizedOutputs`: h264, yuv420p, `avg_frame_rate`, длительности видео и звука,
  AAC 48 кГц стерео. Независимая проверка прогнала настоящий `importReviewMedia` с переупаковкой и
  быстрым прокси на 30, 30000/1001 и 25 fps – проверки прошли, видеопоток `media.mp4` побайтно равен
  слою. Диапазон `tv` `verifyNormalizedOutputs` не проверяет; его гарантирует `layer render` (обе
  ветки нормализации дают `tv`).
- Текущая нормализация не задаёт `-ac`: моно-звук остаётся моно, а импорт требует стерео.
- VP8: 2 потока – 68 с, 4 – 66 с, 8 – 344 с (в 3 раза медленнее одного: перегрузка ядер),
  4 + `-cpu-used 4` – 26 с; PSNR прокси к мастеру 30,5 дБ против 30,7 дБ у `-threads 1`.

## Решения

### Очередь тяжёлых задач

- **Механизм:** N слотов в общей папке машины (`AUTOMONTAGE_HEAVY_DIR`, по умолчанию
  `<os.tmpdir()>/automontage-heavy`). Слот `slot-K/` занимается тем же протоколом, что и
  блокировка проекта – `acquireProjectMutationLease(slotDir)` (атомарный hard link, мёртвый
  владелец на этом же хосте освобождается через `kill(pid, 0) → ESRCH`). Новый протокол блокировок
  не пишется.
- **Слотов** по умолчанию 1 (`AUTOMONTAGE_HEAVY_SLOTS`, целое 1–8). **Ожидание** – опрос раз в 5 с,
  до 3 ч (`AUTOMONTAGE_HEAVY_WAIT_MS`); `0` – не ждать, сразу ошибка `HEAVY_QUEUE_BUSY`.
- **Кто встаёт в очередь:** `layer render` (Remotion + нормализация + G6/G7), `layer import`,
  `automontage preview`, финальные рендеры `scripts/build.js` (lesson и Dynamic) и
  `scripts/motion/build.js` (MotionReel), `automontage master` (в том числе из дублей). Label слота
  содержит только имя папки проекта: он может попасть в браузер Review. Слот берётся до блокировки проекта, чтобы ожидание не блокировало Save и утверждение.
- **Кто не встаёт:** импорт из браузера Review и выбор b-roll (короткие клипы, человек ждёт ответа),
  Whisper, `layer stock`, `layer sheet`, `remotion still`, пульт. Это не ухудшает текущее поведение:
  сегодня они тоже ни с чем не согласованы.
- **Preview из Review** запускается с `AUTOMONTAGE_HEAVY_WAIT_MS=0`: занятая машина даёт сразу
  понятный отказ «машина занята: …» вместо 10-минутного таймаута задания.
- **`busy.js` удаляется:** очередь заменяет опрос `ps` (D-039 называл его «диагностикой, а не
  локом»). Взаимной блокировки двух ожидающих больше нет: ожидающий не держит слот.
- **`automontage queue`** показывает занятые слоты: что выполняется, pid, с какого времени.
- **Тесты** получают собственную папку очереди на каждый тестовый файл:
  `node --require ./tests/helpers/heavy-queue-isolation.cjs` (условие по `NODE_TEST_CONTEXT`), в том
  числе в Windows-задаче CI, которая вызывает `node --test` напрямую.
- **`--no-wait`** у `layer render` теперь значит «не ждать очередь: занято – сразу ошибка» (раньше –
  «запустить, не проверяя машину»).
- **Риск (проверяется при приёмке):** очередь общая, только если у всех агентов одинаковый
  `os.tmpdir()`. Если песочница агента подменяет `TMPDIR`, папку задают явно через
  `AUTOMONTAGE_HEAVY_DIR` в общем env. Повторно использованный pid умершего владельца держит слот,
  пока такой процесс жив (тот же компромисс, что у блокировки проекта).

### Рендер слоя: одно кодирование видео

- `remotion.config.js` подключает `limitedRangeOverride` только при
  `AUTOMONTAGE_LAYER_LIMITED_RANGE=1`; эту переменную ставит лишь `layer render`. Preview и финал
  не меняются.
- После Remotion `layer render` проверяет сырой файл: `yuv420p` + `tv` → нормализуется только звук
  (`-c:v copy`); иначе (override не сработал, другая версия Remotion) – прежняя полная нормализация
  с предупреждением. Обе ветки добавляют `-ac 2`.

### Импорт слоя: переупаковка вместо перекодирования

- `importReviewMedia` получает `masterStrategy: 'encode' | 'remux-if-conforming'` (по умолчанию
  `'encode'`). Только `scripts/layer/import.js` передаёт `'remux-if-conforming'` – после того как
  рендер привязан к проходящему отчёту `layer render` (sha256, G6/G7, текущий исходник).
- Переупаковка разрешена, только если probe загруженного файла соответствует мастеру: h264,
  yuv420p, без поворота, чётные стороны, `avg_frame_rate` равен `outputFps` (±1e-6), AAC 48 кГц
  стерео. Иначе – прежнее перекодирование. `verifyNormalizedOutputs` (в том числе полное
  декодирование) выполняется в обоих случаях без изменений.
- Прокси при `'remux-if-conforming'`: `-threads 4 -cpu-used 4` (импорт держит слот очереди, машина
  не перегружена). Импорт из браузера сохраняет `-threads 1`.
- Override Remotion меняет только аргументы с `-c:v libx264` и вставляет фильтр перед выходным
  файлом; элементы аргументов могут быть числами. При запуске Remotion окружение передаётся целиком
  (`{ ...process.env, AUTOMONTAGE_LAYER_LIMITED_RANGE: '1' }`).

## Не входит

Аппаратный кодер VideoToolbox для preview (несовместим с `--crf`, выигрыш мал – время уходит на
кадры Chrome), очередь для Whisper и импорта из Review, повторные SHA-256 при публикации ассета
(0,4 с на файл в 1080p), параллельное кодирование Remotion (зависит от свободной памяти).
