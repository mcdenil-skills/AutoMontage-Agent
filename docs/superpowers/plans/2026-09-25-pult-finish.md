## Где работать и как тестировать

- Фазы A и B – в мастерской `AutoMontage-Agent-pult` (git worktree, ветка `feat/pult-rolikov`).
- Фазы C–E – в основной папке `AutoMontage-Agent` после слияния.
- Основную папку до слияния не трогать; исключение – дописывать её дневник `memory/`.
- Системный ffmpeg на этом Mac собран без `libwebp`/`drawtext`, поэтому все тесты – с полной
  сборкой в PATH:

```bash
PATH="/opt/homebrew/opt/ffmpeg-full/bin:$PATH" npm test                 # модульные, ~1 мин
PATH="/opt/homebrew/opt/ffmpeg-full/bin:$PATH" npm run test:review-ui   # браузерные, ~1,5 мин
node --test tests/pult-*.test.js                                          # только пульт, ~10 с
PATH="/opt/homebrew/opt/ffmpeg-full/bin:$PATH" npx playwright test tests/pult-ui.spec.js --project=chromium
node scripts/check-release.js && node scripts/check-release.js --base main   # после коммита
```

- `check:release` читает закоммиченное дерево: запускать после коммита.
- В добавленных строках нельзя длинное тире (U+2014) – только «–». Нельзя личные домашние
  пути macOS, Linux и Windows в коде, тестах и документах (даже как пример): pre-commit и
  `check:release` это блокируют.
- Никогда не `--no-verify`, никогда голый `git stash`, никогда `rm -rf`.
- Каждое исправление поведения – сначала падающий тест (TDD), для защиты – тест с вредным
  вводом и рядом тест с нормальным.
