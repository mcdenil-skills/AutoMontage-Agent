# Рабочее качество 1080p – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ролик монтируется в рабочем разрешении 1080p (короткая сторона 1080) вместо 4K исходника; 4K остаётся опцией `--quality source`.

**Architecture:** Разрешение уменьшается один раз – в `automontage master`, который и так полностью перекодирует исходник при нарезке. Слой (`layer new` берёт размер из активного исходника), импорт, preview и final наследуют 1080p без отдельных правок. Preview перестаёт жёстко уменьшать кадр вдвое и считает масштаб от размера композиции. Motion-kit уже масштабируется от канона 1080 (`k = min(width, height) / 1080`), поэтому его не трогаем.

**Tech Stack:** Node.js 20 (CommonJS), ffmpeg filter_complex, Remotion CLI, `node:test`.

**Spec:** аудит `knowledge/montage-speed-audit-2026-10-02.md` (локальный) + решение Дмитрия 2026-10-02: «реально 4K нам не нужно (но может быть как доп. функция)».

## Global Constraints

- Рабочее качество по умолчанию – `1080p`: короткая сторона кадра 1080, пропорции и FPS как у исходника.
- `source` (алиасы `4k`, `native`) – прежнее поведение: родной размер исходника без масштабирования.
- Никогда не увеличивать кадр: исходник с короткой стороной ≤ 1080 остаётся как есть.
- Ширина и высота результата всегда чётные.
- Масштабирование – `scale=W:H:flags=lanczos,setsar=1` внутри того же filter_complex, без второго прохода кодирования.
- Preview: длинная сторона не больше 1920 (`previewScale = min(1, 1920 / max(width, height))`).
- Ветка `feat/working-1080p`, не `main`. Push и merge – только по явной просьбе Дмитрия.
- Перед крупной работой найти или создать Issue через форму `.github/ISSUE_TEMPLATE/` (правило `AGENTS.md`).
- Пользовательские сообщения CLI – по-русски, как в соседнем коде.

## Review Focus

1. Горизонтальный 4K (3840×2160) должен стать 1920×1080, а не 1080×607 – проверяется в Task 1.
2. Телефонный исходник с поворотом 90° хранится как 3840×2160, показывается как 2160×3840. Масштаб берётся от отображаемого размера (`displayDimensions`), иначе кадр сплющится – проверяется в Task 3.
3. Проект в работе с 4K-слоем: следующий `master` по умолчанию станет 1080p, и старый слой перестанет совпадать по размеру. G6 обязан остановить рендер понятной ошибкой, а не тихо смонтировать слой другого размера – проверяется в Task 3 (тест на G6 уже есть, нужен прогон).
4. Дубли (takes) в 4K собираются через `buildTakesMaster` – им нужно то же масштабирование – проверяется в Task 3.
5. Preview старого 4K-проекта должен остаться 1080×1920 (масштаб 0,5), а preview нового 1080p-проекта – 1080×1920 (масштаб 1), а не 540×960 – проверяется в Task 4.

### Task 1: Модуль рабочего качества

**Files:**
- Create: `scripts/working-quality.js`
- Test: `tests/working-quality.test.js`

**Interfaces:**
- Produces:
  - `QUALITIES: ['1080p', 'source']`
  - `parseQuality(value: string) -> '1080p' | 'source'` – алиасы `1080p`, `1080` → `1080p`; `source`, `4k`, `native` → `source`; регистр не важен; иначе `Error('неизвестное качество "<value>": используй 1080p или source')`.
  - `workingSize({ width, height }, quality = '1080p') -> { width, height, scaled: boolean }`
  - `previewScale({ width, height }) -> number`

- [ ] **Step 1: Написать падающие тесты**

```js
test('1080p shrinks vertical and horizontal 4K by the short side', () => {
  assert.deepEqual(workingSize({ width: 2160, height: 3840 }), { width: 1080, height: 1920, scaled: true });
  assert.deepEqual(workingSize({ width: 3840, height: 2160 }), { width: 1920, height: 1080, scaled: true });
  assert.deepEqual(workingSize({ width: 1440, height: 2560 }), { width: 1080, height: 1920, scaled: true });
});
test('1080p never upscales and source keeps native size', () => {
  assert.deepEqual(workingSize({ width: 1080, height: 1920 }), { width: 1080, height: 1920, scaled: false });
  assert.deepEqual(workingSize({ width: 720, height: 1280 }), { width: 720, height: 1280, scaled: false });
  assert.deepEqual(workingSize({ width: 2160, height: 3840 }, 'source'), { width: 2160, height: 3840, scaled: false });
});
test('scaled sides are rounded to even numbers', () => {
  const size = workingSize({ width: 1350, height: 2401 });
  assert.equal(size.width, 1080);
  assert.equal(size.height % 2, 0);
  assert.equal(size.height, 1920);
});
test('parseQuality accepts aliases and rejects unknown values', () => {
  assert.equal(parseQuality('1080'), '1080p');
  assert.equal(parseQuality('4K'), 'source');
  assert.equal(parseQuality('native'), 'source');
  assert.throws(() => parseQuality('720p'), /неизвестное качество/);
});
test('previewScale caps the long side at 1920', () => {
  assert.equal(previewScale({ width: 2160, height: 3840 }), 0.5);
  assert.equal(previewScale({ width: 3840, height: 2160 }), 0.5);
  assert.equal(previewScale({ width: 1080, height: 1920 }), 1);
  assert.equal(previewScale({ width: 720, height: 1280 }), 1);
});
```
