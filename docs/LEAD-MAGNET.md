# Лид-магниты: данные и команды движка

Лид-магнит — материал, который автор обещает зрителю в ролике: страница, PDF и тексты для
раздачи. Агент фиксирует дословную цитату обещания и таймкод, а затем собирает материал под
подтверждённые параметры. Библиотека общая для роликов и находится в `projects/.lead-magnets/`.
Доступны навык `skills/lead-magnet/SKILL.md`, заготовка страницы, PDF и инструменты
референсов (часть 1C), а также решения, просмотр и человеческое утверждение в пульте
с HMAC-защитой (часть 1B). Ниже описан общий путь от обещания до утверждения материала.

## Где что лежит

| Путь | Содержимое |
|---|---|
| `projects/<ролик>/lead-magnet/offers.json` | Обещания: цитата, таймкод, кодовое слово и обещанные единицы |
| `projects/<ролик>/pult/lead-magnet.json` | Решения человека по этому ролику |
| `projects/<ролик>/pult/lead-magnet-refs/<sha>.<ext>` | Загруженные референсы дизайна с проверенным хешем |
| `projects/.lead-magnets/<id>/lead-magnet.json` | Паспорт: слова, обещание, ролики, параметры и ревизии |
| `projects/.lead-magnets/<id>/references/` | Копии референсов с происхождением |
| `projects/.lead-magnets/<id>/vNN/` | `page.html`, `page.pdf`, `content.md`, `facts.json`, выбранные `texts/{dm,telegram,instagram}.txt` |
| `projects/.lead-magnets/<id>/vNN/qa/` | `desktop.png`, `phone-390.png`, `check.json` после проверки |
| `projects/.lead-magnets/<id>/funnel.json` | Состояние воронки, если оно проверено |
| `projects/.lead-magnets/<id>/pult/` | Комментарии и снимки для интерфейса пульта |

Одинаковое кодовое слово может относиться к нескольким материалам. `list --code-word` лишь
предлагает совпадения. «Уже есть готовый» привязывает выбранный материал к ролику сразу при
записи решения; «Разработать новый» всегда создаёт отдельный материал. «Оставить как есть»
сразу фиксирует новую цитату как принятую. Эти автоматические решения во входящие не попадают;
«Обновить под новое» создаёт работу для агента.

## Путь агента

После транскрибации или чтения утверждённого сценария агент сохраняет обещание:
Монтажный агент по навыкам `reel-turnkey`, `reel-from-donor` и `motion-reel` вызывает `offer add`
сразу после получения расшифровки (для аватара — утверждённого сценария), если в ролике есть призыв.

```bash
automontage lead-magnet offer add --project-dir projects/<ролик> --code-word ГАЙД \
  --kind comment-keyword --quote "<дословная цитата>" \
  --units '[{"key":"step","label":"шаг","count":3}]'
automontage inbox
```

`offer add` сверяет цитату с локальной расшифровкой. Для утверждённого сценария допустимы
`--source script --script <файл внутри папки ролика>`. Формат `--units` — JSON-массив
обещанных единиц; точную форму задаёт `schema/lead-magnet-offers.schema.json`. Человек
принимает решение в пульте. После строки «Лид-магнит: запрос r-…» во входящих агент выполняет:

```bash
automontage lead-magnet brand
automontage lead-magnet create --from <ролик> <r-id> --title "<название>"
automontage lead-magnet revision start --id <id>
automontage lead-magnet reference import --id <id> --from <ролик> --path pult/lead-magnet-refs/<файл>
automontage lead-magnet reference shot --id <id> --url <ссылка>
# Для загруженного HTML: reference import, затем reference shot --id <id> --file references/<файл>.html
automontage lead-magnet revision scaffold --id <id> --revision <n>
# Агент заполняет content.md, page.html, facts.json и выбранные texts/*.txt.
automontage lead-magnet pdf --id <id> --revision <n>
automontage lead-magnet check --id <id> --revision <n>
automontage lead-magnet revision publish --id <id> --revision <n>
automontage inbox --accept-lead <ролик> <r-id>
```

Команды `reference import` и `reference shot` выполняются только для референсов из параметров
запроса; без них шаг пропускают. Загруженный файл копируется в библиотеку после проверки хеша.
Ссылка снимается в Chromium, а загруженный HTML открывается без сети и скриптов. Снимки
ограничены папкой материала, записываются с проверкой пути и остаются данными для композиции,
а не источником чужого текста или брендинга.

Если ручной запрос имеет `decision.codeWord: null`, `create` требует `--code-word "<слово>"`.
`brand` показывает, обязателен ли логотип и какие навыки голоса назначены. `scaffold` создаёт
`page.html` и `content.md` из бренд-пака; агент заменяет все `data-lm-todo`, проверяет каждую
ссылку, команду, лицензию и число и записывает источники в `facts.json`. PDF печатается из
готовой страницы локальным Chromium без сетевых запросов; путь страницы и результата защищён
от симлинков и подмены каталога. После последней правки HTML команду `pdf` повторяют.

Новая ревизия получает папку `vNN/` с самодостаточным HTML, PDF, `content.md`, `facts.json` и
текстами, выбранными в параметрах. `check` запускает настоящий Chromium на компьютере и при
ширине 390 px, пишет снимки и `qa/check.json`. Команда возвращает код 1 при красном отчёте
и 0 при зелёном; отчёт сохраняется и выводится в обоих случаях. `publish` требует все файлы и актуальный
отчёт проверки, затем показывает ревизию как черновик. Красные пункты нужно исправить и
повторить `check` до показа человеку. Правки по блокам из `inbox` требуют новой ревизии;
после её публикации каждую отмечают `inbox --accept-lead <id> <c-id>`. Для запроса
«Обновить под новое» служит `promise update --id <id> --from <ролик>`: цитата, таймкод и
обещанные единицы (тип и количество) переносятся в паспорт вместе, затем нужна новая ревизия.
Для запроса проверки воронки есть `funnel set --id <id> --provider chatplace --exists yes|no`.
На этапе 1 агент только читает автоматизацию Chatplace и записывает локальный статус;
создание, изменение и запуск автоматизации не выполняются.
Все команды принимает общий флаг `--projects-dir <путь>`; полный синтаксис:
`automontage lead-magnet --help`.

Запрос отмечают принятым только после выполнения работы. Повторный `create` с тем же запросом
возвращает уже созданный материал без новой папки, даже если запрос уже принят.

## Разметка страницы и проверка

Каждый редактируемый блок страницы получает уникальный `data-lm-block="hero"` или другой
короткий id. Нижний блок со ссылками остаётся даже в режиме «без призыва»,
где содержит только соцсети (без соцсетей — подсказку сохранить страницу). Он всегда помечается `data-lm="cta"`; логотип, если он нужен
бренд-паку, — `data-lm="logo"` на `svg`/`img` или его контейнере. Каждый `<pre>` помещают
в контейнер `data-lm-code` с кнопкой `data-lm-copy`. Обещанные единицы отмечают видимыми
`data-lm-item="<ключ>"`, где ключ совпадает с `units[].key`.

| Красный пункт `check` | Что исправить |
|---|---|
| `promise` | Вернуть дословную цитату на страницу и показать каждую обещанную единицу в нужном числе |
| `cta` | Оставить один блок призыва в конце |
| `phone-width` | Убрать горизонтальную прокрутку и обрезанный текст при 390 px |
| `copy-buttons` | Добавить контейнер и кнопку копирования к каждому `<pre>` |
| `logo` | Добавить логотип, если бренд-пак требует его |
| `header` | Убрать слово «лид-магнит» из заголовка страницы |
| `self-contained` | Встроить локальные ресурсы; страница не должна делать внешние запросы |
| `blocks` | Дать блокам уникальные допустимые id |
| `blocks` с «незаполненные заготовки» | Убрать все `data-lm-todo` и заполнить видимый текст |
| `texts` | Создать выбранные тексты и уложиться в лимиты: личка 1000, Telegram 1024, Instagram 2200 символов |
| `facts` | Проверить источники; исправить утверждение на странице и в `facts.json` либо удалить его из обоих, затем повторить `check` |

`facts.json` хранит `claim`, `source`, `status` (`verified`, `failed`, `unverifiable`) и
необязательную заметку. `failed` и `unverifiable` блокируют утверждение. Отсутствующий или
повреждённый `facts.json` также записывает красный пункт и заменяет прежний зелёный отчёт.
После исправления файла повторите `check`.

Отчёт привязан к странице, фактам, выбранным текстам и обещанию с единицами в паспорте.
Изменение или удаление текста, смена обещания, единиц или выбора текстов требует нового `check`
перед утверждением. Старые отчёты без отпечатка входных данных тоже нужно пересоздать;
история уже утверждённых ревизий сохраняется.

## Свой бренд-пак

Приватный бренд-пак задаётся `LEAD_MAGNET_BRAND=<папка>`; если переменная не задана,
движок ищет папку `lead-magnet/` рядом с корнем `THEMES_EXT`. Например, если `THEMES_EXT`
указывает на приватную папку тем, положите пакет в соседнюю папку `lead-magnet/` либо задайте
её напрямую через `LEAD_MAGNET_BRAND`. Для первого материала пакет не нужен: заготовка
получит нейтральный стиль без логотипа.

На macOS после настройки бренд-пака пересоздайте значок пульта командой
`automontage pult --install-shortcut`; в Windows задайте переменную окружения в настройках пользователя Windows.

Пример `brand.json` для вымышленной студии «Лист»:

```json
{
  "version": 1,
  "name": "Студия Лист",
  "logoRequired": true,
  "logo": "logo.svg",
  "tokens": {
    "colors": { "background": "#F5F4EF", "surface": "#FFFFFF", "text": "#202824", "muted": "#65736A", "accent": "#317A54" },
    "fonts": { "heading": "Oswald", "body": "Onest", "mono": "JetBrainsMono" }
  },
  "fontFiles": ["fonts/Oswald-Bold.ttf", "fonts/Onest-Regular.woff2", "fonts/JetBrainsMono-Regular.woff2"],
  "cta": {
    "title": "Продолжить практику?",
    "text": "Откройте следующую бесплатную памятку.",
    "buttons": [{ "label": "Открыть памятку", "url": "https://example.com/guide" }],
    "utm": "?utm_source=video&utm_campaign={campaign}"
  },
  "socials": [{ "network": "telegram", "label": "Telegram", "url": "https://t.me/example" }],
  "voice": { "skills": [], "rulesFile": null },
  "examples": []
}
```

Файлы `logo.svg` и `fonts/*` лежат в той же приватной папке. `logoRequired: true`
означает, что без логотипа пакет не загрузится, а `check` потребует логотип в странице;
при `false` можно поставить `logo: null`. Имя семейства шрифта берётся из имени файла до
первого `-` или `_`: `Oswald-Bold.ttf` даёт `Oswald`, как в `tokens.fonts.heading`.
Для семейства с пробелом можно использовать имя файла без разделителя, например
`JetBrainsMono-Regular.woff2`, и такое же значение в `tokens.fonts.mono`.
`{campaign}` в UTM заменяется на slug первого кодового слова материала; параметры
добавляются к ссылкам кнопок. При наличии `voice.skills` команда `brand` перечислит навыки
для голоса текста. Полная форма пакета – `schema/lead-magnet-brand.schema.json`.
`socials` — обязательный массив постоянных ссылок автора со значками: `telegram`,
`instagram`, `youtube`, `vk`, `site`; максимум восемь, адреса только HTTPS без логина и пароля.
Для пакета без соцсетей укажите `"socials": []`; существующие пакеты нужно дополнить этим полем.
Соцсети показаны внизу при любом режиме призыва; UTM добавляется только к главным кнопкам.

Приватные файлы не добавляют в публичный репозиторий.

## Пульт

Пульт показывает найденное обещание дословной цитатой, предлагает создать материал,
привязать утверждённый из библиотеки или отказаться. «Нет» можно отменить кнопкой
«🎁 Лид-магнит» в действиях ролика. Окно нового материала собирает подтверждение
обещания, формат, аудиторию, дизайн, референсы, тексты и пожелания.
Пункт 8 «Куда ведём в конце» выбирает призыв бренд-пака (`brand`, также для старых запросов),
свою HTTPS-ссылку с заголовком и надписью кнопки (`link`) или только соцсети (`none`).
Для своей ссылки окно подставляет последнюю из библиотеки; к ней добавятся UTM бренд-пака. После отправки запрос
попадает во входящие агента; привязка готового материала выполняется сразу.

Вкладка «Лид-магнит» показывает страницу в двух ширинах (компьютер и телефон 390), тексты,
проверку, факты, правки, файлы и состояние воронки. Страница открыта в изолированной рамке:
её кнопки работают, переход по ссылке показывается адресом в пульте. Человек может указать
блок страницы кликом в режиме правок или выбрать текст, оставить замечание и передать его
агенту через «Скопировать для агента». Утверждение доступно после зелёной проверки, когда
нет ожидающих правок, и требует галочки о просмотре страницы на обеих ширинах и всех текстов.

Если обещание в ролике-источнике изменилось, вкладка показывает прежнюю и новую цитаты и
даёт человеку выбор: запросить обновление у агента или оставить материал как есть. Если
обещание исчезло из читаемого `offers.json`, доступно только «Оставить как есть»;
«Обновить под новое» выключено до нового обещания. Для связанного ролика решение записывается
в источник, а не в открытую карточку. Когда источник отсутствует или не читается, состояние
неизвестно и кнопок решения нет. Маршруты и защита описаны в
[ARCHITECTURE.md](../ARCHITECTURE.md).

Утверждает лид-магнит только человек после просмотра страницы и текстов. Команды
утверждения в CLI агента нет. Сервер пульта проверяет отдельный HMAC-пропуск конкретной
ревизии и подтверждение просмотра перед вызовом утверждения; одного аргумента
`confirmViewed` в API движка недостаточно как доказательства действия человека.
