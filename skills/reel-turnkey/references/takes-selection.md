# Выбор лучших дублей

Используй этот маршрут, когда пользователь прислал несколько попыток одного ролика: хук записан
несколько раз, середина повторена, CTA переснят. Результат один: новая source revision из лучших
кусков разных дублей. Разные ролики или несколько выходов относятся к пакетному режиму из
`docs/BATCH-REELS-WORKFLOW.md`. Если по запросу нельзя понять, дубли это или разные ролики, задай
один вопрос.

Тем же маршрутом собирается один ролик из нескольких разных записей по сценарию пользователя:
каждая запись регистрируется как дубль (`take-NN` = файл записи), а куски идут в порядке сценария,
а не лучших попыток. Записи должны совпадать по тем же параметрам, что и дубли. На каждом стыке
разных записей и на скачке внутри одной записи ставь смену сцены (B-roll, графика, другой план),
иначе виден прыжок головы.

## Команды

1. Создай workspace из первого файла через `createOrOpenProject()`, но не расшифровывай его
   отдельно: это сделает следующая команда. Сохрани абсолютный путь папки проекта.
2. Добавь остальные дубли. Команда копирует их в `input/takes/`, локально расшифровывает все файлы,
   включая первый, и регистрирует их в `project.json`:

   ```bash
   automontage takes add --project-dir projects/<id> --file take2.mp4 --file take3.mp4
   ```

   Дубли должны совпадать по FPS, размеру кадра с учётом поворота и соотношению сторон пикселя
   и иметь звук. Иначе команда остановится до копирования; перекодировать чужие файлы без просьбы
   пользователя нельзя.

   Расшифровка идёт локально и занимает время: Whisper проходит каждый дубль, включая первый.
   Запускай команду с большим таймаутом и не прерывай её. Если прошлый запуск был прерван,
   команда назовёт оставшиеся файлы; удали их и повтори.
   Если расшифровка не укладывается в таймаут, добавляй по одному дублю за вызов: следующий вызов
   расшифрует только новые файлы.
   Ориентир скорости: на Apple M1 Pro расшифровка занимает примерно треть длительности записи.
3. Получи сводку фраз всех дублей:

   ```bash
   automontage takes pack --project-dir projects/<id> > projects/<id>/edit/takes-packed.md
   ```

   Сводка пишется только в stdout. Если команда завершилась с ошибкой, файл останется пустым:
   исправь причину и повтори, прежде чем выбирать дубли.
4. Выбери дубли по брифу ниже: сам или одним отдельным субагентом.
5. Сохрани выбор в `edit/vNN-takes.json`: `NN` равен следующей ревизии, а `sourceRevision`
   равен активной `source.revision` из `project.json`. Файл целиком, `ranges` берутся из ответа
   брифа:

   ```json
   {
     "version": 1,
     "kind": "takes",
     "sourceRevision": 1,
     "ranges": [
       {"take": "take-02", "start": 1.02, "end": 4.51, "beat": "HOOK",
        "quote": "...", "reason": "..."}
     ]
   }
   ```

   Поля `take`, `start`, `end`, `beat` и `reason` обязательны, `quote` необязательно, других
   полей нет (схема `schema/takes-edit.schema.json`). Без `"kind": "takes"` master примет файл
   за `edit/vNN-source.json` и потребует `fps` и `keep`. Путь в `--edit` указывается от папки
   проекта. Собери master:

   ```bash
   automontage master --project-dir projects/<id> --edit edit/v02-takes.json
   ```

   Master сам ищет паузу в звуке не дальше 0.25 с от каждой границы и ставит разрез в неё, и
   печатает итоговые куски, время стыков (`joints`), сдвинутые границы (`pause`), границы без
   паузы рядом (`no pause near`) и оставленные как есть (`kept`: сдвиг схлопнул бы кусок или
   создал пересечение). Граница без паузы рядом режет речь: выбери другую границу в новом
   `edit/vNN-takes.json`.

6. Проверь стыки до draft. Время стыков печатает master (`joints`). Для каждого стыка посмотри
   кадры по обе стороны (`ffmpeg -ss <время> -frames:v 1`). Звук проверь по уровню, а не на слух:
   в последних 0.1 с куска до стыка и первых 0.1 с после него не должно быть речи громче
   примерно -45 dB (окна по 10 мс, например `ffmpeg -ss <t> -t 0.2 -i <master> -af
   astats=metadata=1:reset=1,ametadata=print:key=lavfi.astats.Overall.Peak_level -f null -`).
   Повторная расшифровка master обрывки слов не ловит. Обрезанное слово, щелчок или повтор
   исправь новым `edit/vNN-takes.json` до draft.
7. Активный транскрипт уже пересчитан master. Не запускай Whisper заново и не создавай
   `transcript/words.json`: исходник и слова бери из `project.json` (`source.localPath`, например
   `input/source-v02.mp4`, и `transcript.words`, например `transcript/words-v02.json`). Этот же
   исходник указывай абсолютным путём (`<project-dir>/input/source-v02.mp4`) в `source` draft и
   во входе команды финального рендера вместо `input/source.mp4`. На стыке разных дублей ставь
   смену сцены. Дальше иди обычным маршрутом.

Чтобы поменять выбор, создай новый `edit/vNN-takes.json` с текущей `sourceRevision`. Master всегда
собирает куски из исходных дублей, а не из прошлой сборки.

## Бриф выбора дублей

```text
Ты монтируешь один ролик из нескольких дублей. Выбери лучший дубль для каждого смыслового блока
и собери блоки в порядке смысла, а не в порядке файлов.

Вход:
- edit/takes-packed.md: фразы всех дублей с таймкодами от начала файла дубля;
- transcript/takes/<take>.json: слова дубля, если граница нужна внутри строки сводки;
- цель ролика и главная мысль: <два предложения из запроса>;
- ожидаемая структура: хук -> проблема -> решение -> польза -> пример -> CTA, или своя;
- оговорки, которых нужно избежать: <список из предварительного прохода по сводке>;
- целевая длительность: <секунды>.

Правила:
- start и end ставь на границы строк сводки; если граница нужна внутри строки, возьми время
  слова из transcript/takes/<take>.json; слово не режется;
- ставь start и end у краёв слов по сводке, запас вручную не добавляй: master сам найдёт
  паузу рядом с каждой границей и сообщит границы без паузы рядом;
- если одинаковый блок есть в нескольких дублях (тот же текст и длительности фраз), не
  переключай дубль: лишний стык – лишний риск;
- фраз, которых нет в речи (часто в конце дубля на тишине: «Продолжение следует», «Субтитры
  сделал»), не бери: это галлюцинации Whisper;
- каждую мысль бери один раз; куски одного дубля не пересекаются, но соседние куски одного
  дубля могут стоять встык: тогда конец первого равен началу второго;
- неизбежную оговорку оставь, если лучшего дубля нет, и напиши это в reason;
- если сумма длиннее цели, убери блок или хвосты и пересчитай сумму.

Выход: только JSON-массив ranges и одна строка с итоговой длительностью:
[{"take": "take-02", "start": 1.02, "end": 4.51, "beat": "HOOK",
  "quote": "...", "reason": "..."}]
```

## Что показать пользователю

В пакете preview добавь таблицу из `references/brief-package.md`: блок, дубль, время в дубле и
причина из `reason`. Выбор дублей не отдельная точка согласования: пользователь меняет его в том же
списке правок, что и остальной preview.

Если пользователь меняет дубль, собери новый master из нового `edit/vNN-takes.json`. Все таймкоды
после изменённого блока сдвинутся, поэтому draft создай заново по новой source revision, не
перенося старые тайминги сцен, и покажи новый полный preview.
